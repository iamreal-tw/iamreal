# 憑證證明的電路：公鑰的位置從結構推導

憑證證明的電路（`certChain`）要從憑證裡取出持卡人的公鑰。上游的做法是由持卡人的裝置提供公鑰的位置（`tbsModulusTagOffset`），電路檢查那個位置的開頭是 `02 82 01 01 00`，再把後面 256 個位元組當成公鑰。我們改成由電路自己算出位置，不再接受裝置提供的位置。

這是 ADR-0008 之外的第二項電路差異，和效期檢查用的是同一段走結構的程式，一起請人檢查。

## 為什麼

上游的稽核報告（`audit_report_v3.md` 的第一項，低風險）指出：電路確認的是「這裡長得像公鑰的開頭」，沒有確認「這裡是憑證的公鑰欄位」。如果憑證別處也出現同樣的 5 個位元組，裝置可以指到那裡，讓電路把別的資料當成公鑰。

以現在內政部的憑證格式，這做不到：那 5 個位元組在憑證裡只出現一次，而且要利用還得握有「那 256 個位元組當成公鑰時」對應的私鑰。所以這不是修補一個能利用的漏洞，是把「靠內政部的格式剛好如此」換成電路自己保證。

它防的是憑證格式將來改變。例如某一代憑證裡出現第二把金鑰，持卡人可以任選一把，一張卡片就有兩個匿名編號。原本的電路會安靜地接受；改過之後，電路只認結構上的公鑰欄位，格式變到走不通時是直接失敗，看得見。

## 做法

- ADR-0008 的效期檢查已經從憑證開頭走到效期欄位。這裡再往下走一步：效期之後是主體名稱，主體名稱之後就是公鑰欄位。
- **主體名稱的長度接受兩種寫法**：127 個位元組以內的短寫法，和 128 到 255 個位元組的長寫法（`81` 加一個位元組）。主體名稱超過 255 個位元組的憑證會被拒絕。主體名稱除了姓名以外固定是 51 個位元組，所以短寫法容得下 25 個中文字的姓名，兩種合起來容得下 68 個中文字。姓名的字數在法律上沒有上限，所以不能只支援短寫法。
- **公鑰欄位的開頭 28 個位元組整段釘死**：RSA 2048 位元金鑰的 `SubjectPublicKeyInfo` 從外層標頭到模數之前的內容是固定的。其他種類或長度的金鑰會被拒絕。
- 公鑰的位置等於「公鑰欄位的起點加 28」。`tbsModulusTagOffset` 不再是輸入。上游原有的檢查（那 5 個位元組、範圍檢查）保留。
- 場合簽章和宣告碼簽章用的電路（`userSig`）不動，匿名編號的算法不變。同一張憑證取出的公鑰和原本相同。

## 量測

用 circom 2.2.3 編譯（2026-11-14）。「草稿」是 ADR-0008 和這一項都加上去的版本。

| | 上游 `97210ba` | 只有 ADR-0008 | 草稿 |
|---|---|---|---|
| `certChainRS2048` 的約束數量 | 1,841,657 | 1,833,609 | 1,838,240 |
| `certChainRS4096` 的約束數量 | 2,033,081 | 2,025,033 | 2,029,664 |

這一項多 4,631 條，總數仍然比上游少。

草稿用上游的兩份測試資料和 11 張自製的測試憑證跑過，結果都符合預期：

| 測試憑證 | 結果 |
|---|---|
| 一般的憑證 | 通過 |
| 主體名稱 128 到 255 個位元組 | 通過 |
| 主體名稱超過 255 個位元組 | 拒絕 |
| 昨天到期 | 拒絕 |
| 今天最後一秒到期 | 通過 |
| 明天才生效 | 拒絕 |
| 到期日在 2051 年（`GeneralizedTime`） | 拒絕 |
| 序號只有 1 個位元組；序號 17 個位元組 | 通過 |
| 發證者名稱 128 個位元組以上 | 拒絕 |
| 持卡人的金鑰是 RSA 4096 位元 | 拒絕 |

## Considered Options

- **維持上游的做法**：不能利用，差異也比較小。但格式改變時不會有任何警訊。
- **維持上游的做法，另外加一個測試**，定期檢查那 5 個位元組在真的憑證裡只出現一次（稽核報告的建議之一）：能提早發現格式改變，但測試看不到每一張憑證。
- **只支援短寫法的主體名稱**：電路更簡單，但會把姓名特別長的持卡人擋在外面。

## Consequences

- 和上游的差異從一項變成兩項。兩項分成兩個提交，可以分開看。
- 瀏覽器端準備輸入的程式少一個欄位，不用再解析憑證找公鑰的位置。
- 憑證證明現在所有取值的位置都由結構決定，沒有一個由裝置提供。
- 主體名稱超過 255 個位元組、發證者名稱超過 127 個位元組、金鑰不是 RSA 2048 位元的憑證過不了卡。這些都是看得見的失敗。內政部簽發的真憑證我們只核對過少數幾張，上線前要用不同年份的卡片試過，其中最好有姓名很長的。
- 公鑰的指數（`65537`）電路仍然沒有從憑證裡讀出來核對，這一點和上游相同，不在這次的範圍。
