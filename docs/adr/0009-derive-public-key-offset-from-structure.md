# 電路從憑證的結構找出公鑰

電路要從憑證裡取出持卡人的公鑰。公鑰的位置由電路自己從憑證的結構算出來，不接受持卡人的裝置提供的位置。

PSE 的電路是由裝置提供位置，電路檢查那個位置的開頭是 `02 82 01 01 00`，再把後面 256 個位元組當成公鑰。

## 為什麼

PSE 的稽核報告（`audit_report_v3.md` 的第一項，低風險）指出：那種做法確認的是「這裡長得像公鑰的開頭」，沒有確認「這裡是憑證的公鑰欄位」。如果憑證別處也出現同樣的 5 個位元組，裝置可以指到那裡，讓電路把別的資料當成公鑰。

以現在內政部的憑證格式，這做不到：那 5 個位元組在憑證裡只出現一次，而且要利用還得握有「那 256 個位元組當成公鑰時」對應的私鑰。所以這不是修補一個能利用的漏洞，是把「靠內政部的格式剛好如此」換成電路自己保證。

它防的是憑證格式將來改變。例如某一代憑證裡出現第二把金鑰，持卡人可以任選一把，一張卡片就有兩個匿名編號。由裝置提供位置的電路會安靜地接受；從結構找的電路只認結構上的公鑰欄位，格式變到走不通時是直接失敗，看得見。

## 做法

- 效期檢查（ADR-0008）已經從憑證開頭走到效期欄位。這裡再往下走：效期之後是主體名稱，主體名稱之後就是公鑰欄位。
- **主體名稱的長度接受兩種寫法**：127 個位元組以內的短寫法，和 128 到 255 個位元組的長寫法（`81` 加一個位元組）。主體名稱超過 255 個位元組的憑證會被拒絕。主體名稱除了姓名以外固定是 51 個位元組，所以短寫法容得下 25 個中文字的姓名，兩種合起來容得下 68 個中文字。姓名的字數在法律上沒有上限，所以不能只支援短寫法。
- **公鑰欄位的開頭 28 個位元組整段釘死**：RSA 2048 位元金鑰的 `SubjectPublicKeyInfo` 從外層標頭到模數之前的內容是固定的。其他種類的金鑰會被拒絕。
- **模數剛好 2048 位元**：模數的第一個位元組必須不小於 `0x80`。只靠釘死的長度擋不住較短的金鑰：在前面多補一個 0，長度欄位照樣寫得出 2048 位元的樣子。
- 公鑰的位置等於「公鑰欄位的起點加 28」。

## 測試

| 測試憑證 | 結果 |
|---|---|
| 一般的憑證 | 通過 |
| 主體名稱 128 到 255 個位元組 | 通過 |
| 主體名稱超過 255 個位元組 | 拒絕 |
| 序號只有 1 個位元組；序號 17 個位元組 | 通過 |
| 發證者名稱 128 個位元組以上 | 拒絕 |
| 持卡人的金鑰是 RSA 4096 位元 | 拒絕 |
| 持卡人的金鑰是 2047 位元，長度欄位照 2048 位元寫 | 拒絕 |
| 憑證別處有一段假的公鑰開頭 | 通過，取到的仍然是結構上的那把公鑰 |

對照用的 PSE 電路分支上也改成同樣的做法，逐案比對的結果相同（ADR-0012）。

## Considered Options

- **由裝置提供位置**：以現在的格式不能利用。但格式改變時不會有任何警訊。
- **由裝置提供位置，另外加一個測試**，定期檢查那 5 個位元組在真的憑證裡只出現一次（稽核報告的建議之一）：能提早發現格式改變，但測試看不到每一張憑證。
- **只支援短寫法的主體名稱**：電路更簡單，但會把姓名特別長的持卡人擋在外面。

## Consequences

- 電路所有取值的位置都由結構決定，沒有一個由裝置提供。持卡人的裝置準備輸入時不用解析憑證找位置。
- 主體名稱超過 255 個位元組、發證者名稱超過 127 個位元組、金鑰不是 RSA 2048 位元的憑證過不了卡。這些都是看得見的失敗。內政部簽發的真憑證我們只核對過少數幾張，上線前要用不同年份的卡片試過，其中最好有姓名很長的。
- 公鑰的指數（`65537`）在 ADR-0010 裡一起釘死。
- 這項改動已經向 PSE 提出（[ethereum/zkID#117](https://github.com/ethereum/zkID/pull/117)）。
