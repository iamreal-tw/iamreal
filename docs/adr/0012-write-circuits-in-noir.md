# 電路用 Noir 自己寫，PSE 的電路留作對照

零知識證明的電路改成我們自己用 Noir 寫，用 Barretenberg 的 UltraHonk 算證明和驗證。PSE zkID 的 circom 電路不再是我們執行的電路，改當對照：同一批測試資料，兩邊要給出相同的接受或拒絕。

這份決定取代 ADR-0001（PSE 的電路只加檢查，不放寬）。

## 為什麼

ADR-0001 選擇以上游的電路為基礎，是因為自己寫的電路我們審不動。這個顧慮仍然成立。改變的是另一邊的代價，實作之後才量得出來：

- **用 PSE 的電路，持卡人第一次過卡要下載約 877 MB。** 它的證明系統（Spartan2）每份電路各有一把證明金鑰，一把 588 MB，一把 275 MB。這在手機上幾乎不可行。Noir 的版本要下載約 21 MB。
- **用 PSE 的電路，重驗一筆紀錄要先下載約 860 MB 的驗證金鑰。** 「任何人都能重驗」是這個專案公開程式的理由（見 `CLAUDE.md` 的目錄表）。Noir 的版本是一個 25 MB 的驗證程式，加上 3,680 個位元組的驗證金鑰。
- **以 PSE 的電路為基礎的好處比當初小。** 我們需要四項它沒有的檢查（ADR-0008 到 0011），加了之後執行的電路和 PSE 發布的不再相同；PSE 的目錄標示是概念驗證，稽核是 AI 輔助的。
- **Noir 的電路比較好讀。** 同樣的內容，Noir 約 460 行，circom 約 1,809 行（都不含引用的函式庫）。circom 要分開寫「算值」和「加約束」，漏一條約束不會報錯；Noir 沒有這個分別。
- **現在還沒有人宣告。** 換電路會改變匿名編號的算法，名額要全部重來。上線之後就換不了。

## 做法

- **一份電路，每次過卡一份證明**（ADR-0013）。它檢查：
  - 內政部的發證金鑰對憑證的簽章。
  - 憑證照 DER 結構走得通；在效期內（ADR-0008）；公鑰從結構上的位置取出（ADR-0009）；金鑰用途是簽章（ADR-0010）；是國民的正卡（ADR-0011）；序號不在廢止清冊上。
  - 卡片對場合字串的簽章，匿名編號是這個簽章的雜湊。
  - 卡片對宣告碼的簽章（ADR-0002）。
- **雜湊用 Poseidon2**（BN254 的純量體，狀態寬度 4，8 加 56 輪）。匿名編號和廢止清冊的樹都用它。
- **廢止清冊的樹自己建。** 結構和 circomlib 的稀疏雜湊樹相同（128 層），雜湊是 Poseidon2。PSE 的樹在另一個體上，樹根和路徑不能沿用。
- **通用參數**來自 Aztec 的 Ignition 儀式。參數檔放在我們自己的站上，程式裡釘住它的 SHA-256。
- **函式庫釘在特定版本**：RSA 和大數運算用 zkPassport 維護的 `noir_rsa`、`noir-bignum`，SHA-256 用 `noir-lang/sha256`。
- **PSE 的 circom 電路留在我們公開的分支上**，加了同樣的四項檢查，當對照用。電路的各個部分（憑證的檢查、簽章的檢查）各自和它逐案比對；每次改電路都要重跑。

## 量測

原型（2026-11-15）。機器是 Apple M1 Max 和 iPhone 14 Pro，發證金鑰 RS4096。「PSE 的電路」是加了四項檢查的對照版本。

| | PSE 的電路 | Noir 的電路 |
|---|---|---|
| 第一次過卡要下載 | 約 877 MB | 約 21 MB |
| 驗證金鑰 | 588 MB 和 275 MB | 3,680 個位元組 |
| 一筆事件的證明 | 113 KB 加兩份 78 KB | 14.7 KB |
| 原生驗證 | 每份 1.6 到 2.5 秒 | 0.01 秒 |
| 原生算證明的記憶體 | 最高 2.3 GB | 約 0.6 GB |
| 原生算證明 | 約 4 秒 | 約 1.1 秒 |
| iPhone 14 Pro 的 Safari，一次過卡 | 沒有試 | 5.2 到 5.6 秒 |

- PSE 的電路的數字是用 RS2048 的發證金鑰量的；它一次過卡要算三份證明。
- iPhone 上單次過卡的記憶體峰值約 750 MB；Safari 的網頁行程在 1.4 到 1.5 GB 附近會被系統結束（細節見 ADR-0013）。
- 沒有量：Android、較舊的手機、原生的手機 app。

**逐案比對**：把 PSE 那邊的測試案例搬過來，同一份位元組同時餵給兩邊。除了有意的差異（ADR-0013 的種類檢查），接受或拒絕全部相同。有 3 個案例在 Noir 這邊不適用，因為 Noir 的電路沒有那個輸入（序號由電路自己讀；卡片簽的字固定是 31 個位元組）。

## Considered Options

- **維持 ADR-0001**：不用自己對整份電路負責。但第一次過卡要下載約 877 MB，重驗要約 860 MB，這兩件事會讓專案的兩個主要承諾都打折。
- **維持 circom，換一套金鑰比較小的證明系統**：電路不用重寫。但上游的電路寫在 secq256r1 這個體上，是為 Spartan2 選的；換證明系統等於換體，雜湊和樹一樣要重來，而且沒有現成的組合可以直接用。沒有實際評估。
- **用 Poseidon 而不是 Poseidon2**：Poseidon 發表得早四年，Go 有現成的稀疏雜湊樹函式庫。但電路大四成以上，會超過 2 的 18 次方這個級距，通用參數、記憶體、時間都跟著加倍；在 iPhone 的 Safari 裡要另外指定參數才跑得動，記憶體貼近系統的上限。Poseidon2 在 Go 和 JavaScript 都有獨立的實作，我們實際跑過，值和電路相同。

## Consequences

- **整份電路由我們負責。** 上游的審查和修補不再適用於我們執行的電路。對外不說「電路經過稽核」，只說做過哪些檢查、是誰做的。
- **上線前的檢查分兩層。** 第一層是多個獨立的 AI 代理各自檢查，加上和 circom 版本的比對。做了兩輪，每輪六個代理，另有兩萬多筆隨機產生的憑證和簽章同時餵給兩邊；沒有找到能讓電路接受不該接受的東西的反例。方法和結果和電路程式一起公開。第二層是請懂密碼學的人檢查，還沒有找到人。在第二層完成之前，對外寫明「經過 AI 輔助的檢查，沒有經過人工稽核」。
- **函式庫的預設不一定符合我們的用法。** 原型就遇到一個：RSA 的函式庫不檢查簽章小於模數，同一個簽章加上模數後仍然驗得過，一張卡片會有不只一個匿名編號。檢查時又找到一處：大數函式庫只在內部的乘法裡順帶檢查簽章每一段的範圍，同一個簽章換一種分段寫法也是另一個匿名編號。兩處都改成由我們自己的電路檢查，並加了測試。這類問題要一直提防，升級函式庫時要重跑這些測試。
- **一張卡片一個匿名編號，靠兩件事。** 簽章的寫法只有一種，這由電路保證（小於模數、每一段是標準寫法）；同一段字只有一個驗得過的簽章，這靠持卡人選不了自己的金鑰（ADR-0011）。
- **證明系統依賴一場可信設定儀式**（Aztec 的 Ignition，2019 到 2020 年）。參數是通用的，不綁電路；只要參與者裡有一個人誠實，參數就是安全的。PSE 用的 Spartan2 沒有這個前提。
- **匿名編號的算法改變。** 這是上線前最後一次能改。
- **廢止清冊的樹沒有 PSE 的版本可以對照。** 建樹的程式（`crl/`）要讓任何人拿內政部的清冊重建出相同的樹根。
- **Go 沒有官方的驗證函式庫。** 目前確認可行的是呼叫 `bb verify` 這個指令。要不要改成連結函式庫，之後再決定。
- **依賴 Aztec 和 zkPassport 維護的工具和函式庫。** 這些函式庫的說明標示為實驗性質。釘住版本，升級時重跑逐案比對。
- 電路的規則是：行為和對照的 circom 電路相同；有意的差異各有一份 ADR（`CLAUDE.md` 的硬限制第一條）。
- 四項檢查裡的三項已經向 PSE 提出（[ethereum/zkID#117](https://github.com/ethereum/zkID/pull/117)、[#118](https://github.com/ethereum/zkID/pull/118)）。
