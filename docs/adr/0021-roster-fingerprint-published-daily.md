# 名冊每天公布一個指紋，紀錄不串成鏈

名冊每天公布一次**名冊指紋**：一個值，涵蓋第 1 筆到公布那一刻的最後一筆紀錄和它們的順序。每天的日期、筆數、名冊指紋寫成指紋檔的一行，和名冊一起公開。紀錄本身不帶前一筆的雜湊；紀錄的雜湊只代表那一筆。這一份取代 ADR-0005 的最後一段。

留著任何一天那一行的人，查得出那天以前的紀錄有沒有被拿掉、調換順序，或營運者給了別人不同的名冊。偽造和竄改一筆紀錄本來就被證明擋住（ADR-0004），名冊指紋管的是拿掉、順序和給不同的人不同的名冊。

查不出的事：

- 當天還沒公布的紀錄不在保證內。
- 沒有人留著舊的名冊指紋時，營運者能整份重算。指紋檔另外放到營運者改寫不了的地方之前，這要靠有人留存。
- 只留著單筆紀錄的雜湊，查不出它之前的紀錄被動過。

理由：

- **逐筆的鏈沒有多保證什麼。** 鏈尾也只在每天公布一次；當天還沒公布的紀錄，營運者重算整條鏈就能拿掉或調換。兩種做法外人查得出的事，只差上面的最後一項。
- **寫入變簡單。** 每筆紀錄帶前一筆的雜湊時，寫入要先讀上一筆、算完才能寫。拿掉之後，寫入只需要一個序號。
- **能算出來的就不存。** 前一筆的雜湊從名冊檔案的上一行算得出來，名冊指紋也是從整份名冊算出來的（`spec/record.md` 的原則）。
- **算法之後換得動。** 名冊指紋不寫在紀錄裡，換一種算法或多公布一種，只改指紋檔，已經寫入的紀錄不動。

## Considered Options

- **每筆紀錄帶前一筆的雜湊，串成一條鏈**（ADR-0005 原本的最後一段）：多的保證只有「留著單筆紀錄雜湊的人也查得出之前的變動」，代價是寫入多一步，而且鏈寫進紀錄之後換不掉。
- **兩者都有**：鏈的保證已經被名冊指紋涵蓋，多一樣要寫規格、要檢查的東西。
- **後台對每筆寫入簽一張收據**：能把保證做到逐筆，但後台要保管一把簽章金鑰，持卡人要保管收據。

## Consequences

- 紀錄的序號（`seq`）留著：名冊規則照這個順序判斷，名冊目錄照它切檔。
- 名冊指紋的算法寫在 `spec/record.md`。先用滾動的雜湊：拿前一筆為止的名冊指紋和這一筆紀錄的雜湊再雜湊一次，每天只算新增的紀錄。名冊大到重驗的人下載不了整份時，要不要加上 Merkle 樹根另外決定。
- API 顯示的是最近一次公布的名冊指紋和筆數。
- 指紋檔另外放到哪裡還沒定；之後決定，不必改紀錄的格式。
