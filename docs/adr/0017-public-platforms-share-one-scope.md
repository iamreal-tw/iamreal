# 公開平台共用一個場合，同一張卡片宣告的帳號列在一起

公開名冊只有一個場合。一張卡片在所有公開平台用同一個匿名編號，在每個平台各有一個名額。同一張卡片宣告的帳號，在島民證明的頁面上列在一起。

場合字串是 `iamreal:public:0_______________`；測試用 `iamreal-test:public:0__________`。平台不再寫在場合字串裡：一筆紀錄帶這張卡片的整份帳號清單，每個平台最多一個帳號，宣告碼由整份清單算出。一次過卡處理所有平台，替一份清單做的證明不能當成另一份的。

理由：

- **公開的時間線藏不住同一張卡片。** 每個平台各用一個匿名編號時，編號本身對不起來，但名冊公開每一筆紀錄的日期和順序。同一個人在兩個平台過卡的時間相近，次數多了就比對得出來；換新卡時，兩個平台的舊編號同時停住、新編號同時出現。我們評估過把時間放粗、整批公布：照我們的模型，每季公布一批、九成的人每季都過卡，8 年後和目標樣式相同的卡片約剩 3%。能延後，不能避免。
- **看起來分開、其實查得出來，比明講更糟。** 持卡人會因為相信帳號是分開的，而宣告一個不想被連起來的帳號。紀錄公開之後收不回來（ADR-0004）。
- **過卡證明的是卡片，不是帳號。** 卡片還有效、持卡人拿得出卡片和 PIN，這件事不分平台。

規則：

- 一筆紀錄宣告的是這張卡片現在的整份帳號清單；沒有列出的平台就是沒有宣告。
- 空的清單是收回所有帳號，只在這張卡片現在有帳號時接受；沒有宣告任何帳號的卡片送空的清單，那一筆無效。
- 一張卡片在每個平台各有一個名額，同一時間只能宣告給那個平台的一個帳號。
- 上次過卡日跟著卡片：每次過卡都重新簽整份清單，這張卡片宣告的所有帳號一起更新。
- 更換的次數每個平台各算：一張卡片在一個平台終身最多更換 5 次（ADR-0018）；一天內紀錄的上限每張卡片合計。
- 增加平台是在平台的表上加一列，不產生新的匿名編號。第一次上線，表上只有 Threads。

## Considered Options

- **每個平台一個場合，過卡前提醒持卡人錯開時間**：安全交給持卡人讀不讀提醒。
- **每個平台一個場合，時間放粗、整批公布**：見上面第一點。代價是宣告後最久一個月才看得到、廢止檢查最久延後一季。
- **名冊不記再次過卡**：時間線的線索大多消失，但頁面上看不出一筆宣告是新是舊，舊卡留下的名額分辨不出來。
- **共用場合，但讓持卡人選擇帳號要不要列在一起**：不列出來的帳號仍然查得到，回到第二點理由。

## Consequences

- **承諾的範圍變小，要在過卡之前講明白。** 「查不出持卡人是誰」不變。不再說公開平台上的帳號互相連不起來。有兩個不想被連在一起的帳號的人，只宣告其中一個；畫面在第一步（輸入 PIN 之前）和確認的那一步說明，宣告的帳號會公開列在同一張島民證明上。裝置上只有一個平台可以填時沒有別的帳號可以列，這一段不顯示。
- **列在一起不代表帳號主人承認。** 任何持卡人都可以宣告任何帳號（ADR-0003），所以一張卡片可以把別人的帳號和自己的帳號列在一起。頁面的說法是「這張卡片宣告的帳號」，不說「同一個人的帳號」；每個帳號有沒有連回，由訪客到那個帳號的個人檔案上各自確認。
- **能讓卡片簽章一次的人，查得出這張卡片宣告的所有公開帳號**（ADR-0004 的後果，範圍從一個平台變成全部）。
- **不公開的用途不用這個場合。** 其他服務的場合以 `S` 開頭（ADR-0007），匿名編號和公開名冊上的不同，結果不寫進公開名冊。
- **上線後分不回去。** 要讓各平台的匿名編號重新分開，只能升版本，所有持卡人重新宣告。
- 版本升級會讓所有平台的名額一起作廢。
