# 證明紀錄每天公布一個指紋，紀錄不串成鏈

> 補充：指紋檔和其他公開的檔案放在 `data.iamreal.tw`，指紋檔另外由獨立的程式庫每天抄一份（ADR-0027）。

證明紀錄每天公布一次**指紋**：一個值，涵蓋第 1 筆到公布那一刻的最後一筆紀錄和它們的順序。每天的日期、筆數、指紋寫成指紋檔的一行，和證明紀錄一起公開。紀錄本身不帶前一筆的雜湊；紀錄的雜湊只代表那一筆。這一份取代 ADR-0005 的最後一段。

留著任何一天那一行的人，查得出那天以前的紀錄有沒有被拿掉、調換順序，或維護者給了別人不同的證明紀錄。偽造和竄改一筆紀錄本來就被證明擋住（ADR-0004），指紋管的是拿掉、順序和給不同的人不同的證明紀錄。

查不出的事：

- 當天還沒公布的紀錄不在保證內。
- 沒有人留著舊的指紋時，維護者能整份重算。指紋檔另外放到維護者改寫不了的地方之前，這要靠有人留存。
- 只留著單筆紀錄的雜湊，查不出它之前的紀錄被動過。

理由：

- **逐筆的鏈沒有多保證什麼。** 鏈尾也只在每天公布一次；當天還沒公布的紀錄，維護者重算整條鏈就能拿掉或調換。兩種做法外人查得出的事，只差上面的最後一項。
- **寫入變簡單。** 每筆紀錄帶前一筆的雜湊時，寫入要先讀上一筆、算完才能寫。拿掉之後，寫入只需要一個序號。
- **能算出來的就不存。** 前一筆的雜湊從紀錄檔案的上一行算得出來，指紋也是從整份證明紀錄算出來的（`spec/record.md` 的原則）。
- **算法之後換得動。** 指紋不寫在紀錄裡，換一種算法或多公布一種，只改指紋檔，已經寫入的紀錄不動。

## Considered Options

- **每筆紀錄帶前一筆的雜湊，串成一條鏈**（ADR-0005 原本的最後一段）：多的保證只有「留著單筆紀錄雜湊的人也查得出之前的變動」，代價是寫入多一步，而且鏈寫進紀錄之後換不掉。
- **兩者都有**：鏈的保證已經被指紋涵蓋，多一樣要寫規格、要檢查的東西。
- **後台對每筆寫入簽一張收據**：能把保證做到逐筆，但後台要保管一把簽章金鑰，持卡人要保管收據。
- **指紋用 Merkle 樹根，或滾動的雜湊之外再加一個樹根**：樹能讓人只拿一筆紀錄加幾十個雜湊，就確認它在證明紀錄裡，或確認新的證明紀錄只是在舊的後面加東西。包含證明回答不了查詢方要問的事：一筆紀錄是不是偽造的由證明擋住（ADR-0004），查詢方要知道的是這張卡片後面有沒有更新的一筆，包含證明說不出來。剩下的好處是隔很久才檢查一次的人不必拿中間每一筆的雜湊；雜湊清單一年約 19 MB（一年 60 萬筆時），用不到。代價是規格多一份樹的算法和標準答案。樹根從同一批紀錄的雜湊算得出來，之後要加，過去每一天的都能補算。

## Consequences

- 紀錄的序號（`seq`）留著：紀錄規則照這個順序判斷，紀錄目錄照它切檔。
- 指紋用滾動的雜湊，細節寫在 `spec/record.md`：空的證明紀錄是 64 個 0；加入第 n 筆後的指紋是 SHA-256(`iamreal-fingerprint-v1` LF 加入第 n−1 筆後的指紋 LF 第 n 筆紀錄的雜湊)，兩個值都寫成 64 個小寫十六進位字元。每天只算新增的紀錄。
- 和證明紀錄一起公開一份**雜湊清單**：每筆紀錄的雜湊照順序排，切檔的方式和紀錄目錄相同，寫滿的檔不再變；每一檔的開頭附上前一檔結尾的指紋。留著舊的指紋的人，拿那之後的雜湊清單（每筆 32 位元組，寫成十六進位 64 個字元）就能檢查，不必下載整份證明紀錄；要確認某一筆在公布的證明紀錄裡，從它所在的那一檔拿起。雜湊清單和每檔開頭的值都是從證明紀錄算得出來的，重驗整份的人會核對。
- 只拿雜湊清單檢查的人，確認的是紀錄沒有被拿掉、順序沒有變、沒有人拿到不同的證明紀錄；每一筆紀錄本身驗不驗得過，要拿整筆紀錄才查得出。
- 不提供包含證明，上線時不加 Merkle 樹根。重開的條件：證明紀錄接近 1,000 萬筆（雜湊清單約 320 MB），或有人拿具體的用途來要包含證明。
- API 顯示的是最近一次公布的指紋和筆數。
- 指紋檔另外由獨立的公開程式庫每天抄一份（ADR-0027），紀錄的格式不變。
