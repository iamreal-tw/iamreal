# PSE 的電路原樣使用，不修改

零知識證明用的是 PSE zkID 團隊的電路（[privacy-ethereum/zkID](https://github.com/privacy-ethereum/zkID) 的 `wallet-unit-poc/circom/`）。我們把它釘在一個特定的 commit，原樣使用，一行都不改。新的功能只能靠兩種方式做：改變卡片簽的字串，或把多份證明組合起來。做不到的功能就不做。

理由：

- 電路的修改我們審不動。少一條約束，證明就可能被偽造，或洩漏持卡人的身分，而且從外面看不出來。
- 原樣使用時，我們公布使用的 commit 和檔案雜湊，任何人都能確認它和 PSE 發布的相同。別人對這份電路做的審查和修補，我們直接受益；改過的版本只有我們自己看過。
- 匿名編號怎麼算寫在電路裡。換成算法不同的電路，所有持卡人的匿名編號都會變，名額要全部重來。

ADR-0008（proposed）提議開一個例外：憑證證明的電路加上效期檢查。

## Considered Options

- **分支出來修改**（例如讓電路直接綁定題目）：功能上最乾淨，但要專業稽核，而且之後 PSE 的修補要自己合併。
- **自己寫電路**：同樣的問題，更嚴重。

## Consequences

- **原樣使用不等於這份電路已經被證明安全。** 以 commit `97210ba`（2026-07-15）為準，程式庫裡的稽核報告（`wallet-unit-poc/circom/audit_report_v3.md`）寫明是用 AI 輔助的方法做的，範圍不含外部工具偵測的約束不足問題、引用的函式庫和證明後端；目錄名稱也標示它是概念驗證。我們沒有找到第三方的人工稽核報告。所以對外不說「電路經過稽核」，只說「用的是 PSE 公開的電路，沒有修改」。
- 公開上線前要請懂密碼學的人檢查我們怎麼使用這份電路，並決定釘在哪一個 commit。
- 每次過卡要算三份證明，而不是一份合併的證明（見 ADR-0002）。
- 需要改電路才做得到的功能不在範圍內。
