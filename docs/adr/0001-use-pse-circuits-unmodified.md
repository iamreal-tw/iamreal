# PSE 的電路只加檢查，不放寬

> 2026-11-15 由 ADR-0012 取代：電路改成自己用 Noir 寫，PSE 的電路留作對照。下面是當時的決定，保留作紀錄。

零知識證明用的是 PSE zkID 團隊的電路（[ethereum/zkID](https://github.com/ethereum/zkID) 的 `RSA-X.509-Cert` 分支，`wallet-unit-poc/circom/`；程式庫原本在 `privacy-ethereum/zkID`）。我們把它釘在一個特定的 commit，以它為基礎，只做符合下面四條的修改：

1. **只加檢查，不放寬檢查。** 上游接受的憑證和簽章，我們可以拒絕；上游拒絕的，我們不接受。
2. **簽章的電路（`userSig`）和匿名編號的算法不動。**
3. **每一項差異一份 ADR、一個提交**，寫明理由和量測。分支公開，任何人都能和上游比對。
4. **每一項差異都要另外請人檢查後，才能用在正式的場合字串上。**

其他的新功能只能靠兩種方式做：改變卡片簽的字串，或把多份證明組合起來。做不到的功能就不做。

目前的差異：

- ADR-0008：憑證證明加上效期檢查。
- ADR-0009：憑證證明裡公鑰的位置從結構推導。
- ADR-0010：憑證證明檢查金鑰用途是簽章。
- ADR-0011：憑證證明只認國民的正卡。

理由：

- 電路的修改我們審不動。少一條約束，證明就可能被偽造，或洩漏持卡人的身分，而且從外面看不出來。只加檢查時，做錯最可能的後果是真的持卡人過不了卡，這是看得見的失敗；它不會讓上游擋得住的假證明過關。
- 以上游為基礎時，我們公布使用的 commit 和每一項差異，任何人都能確認其餘的部分和 PSE 發布的相同。別人對上游電路做的審查和修補，沒有被我們改到的部分仍然適用。
- 匿名編號怎麼算寫在電路裡。換成算法不同的電路，所有持卡人的匿名編號都會變，名額要全部重來。

這份決定原本是「原樣使用，一行都不改」（2026-11-13）。2026-11-14 發現原樣使用時過期的憑證過得了憑證證明（ADR-0008），改成現在的規則。

## Considered Options

- **原樣使用，一行都不改**：最容易說明，也不需要自己請人檢查電路。但上游沒做的檢查只能在電路外面繞路補，有的補不了。
- **分支出來自由修改**（例如讓電路直接綁定題目）：功能上最乾淨，但改變電路功能的修改出錯時不一定看得見，要專業稽核，而且之後 PSE 的修補要自己合併。
- **自己寫電路**：同樣的問題，更嚴重。

## Consequences

- **以上游為基礎不等於這份電路已經被證明安全。** 以 commit `97210ba`（2026-07-15）為準，程式庫裡的稽核報告（`wallet-unit-poc/circom/audit_report_v3.md`）寫明是用 AI 輔助的方法做的，範圍不含外部工具偵測的約束不足問題、引用的函式庫和證明後端；目錄名稱也標示它是概念驗證。我們沒有找到第三方的人工稽核報告。所以對外不說「電路經過稽核」，只說「用的是 PSE 公開的電路，加了哪幾項檢查」，並指向差異。
- 公開上線前要請懂密碼學的人檢查我們怎麼使用這份電路、我們加的每一項檢查，並決定釘在哪一個 commit。
- 電路、見證產生器、金鑰、瀏覽器端的證明套件、驗證程式都是自己的版本。上游修了別的問題時要自己合併。
- 每次過卡要算三份證明，而不是一份合併的證明（見 ADR-0002）。
- 改變電路功能的修改（不只是加檢查）不在範圍內，要做得先改這份決定。
- 「只加檢查」也可能出錯：新加的約束本身寫得不夠，檢查就形同沒加。這種錯誤的後果不比原樣使用更糟，但會讓我們對外說的話不成立，所以第 4 條不能省。
