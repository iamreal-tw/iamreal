# 測試網站是同一個 Worker 專案的另一個環境，只收真卡片

測試名冊放在一個測試網站上。它主要用在上線前的封閉試用：邀少數人用真卡片和自己的 Threads 帳號走完整個流程，網站不宣傳。它也是預演的環境，每一版先部署到這裡，再部署到正式的網站。上線後它繼續留著，給手機 app 的測試者用，也用來試各種狀況。只有一個測試網站。

## 怎麼部署

測試網站和正式網站是同一個 Worker 專案的兩個環境（wrangler 的 environments），放在同一個 Cloudflare 帳號。兩個環境的程式碼相同，每個環境各有一份：

- 自己的 Durable Object、R2 儲存桶、清冊鏡像的排程、網址、密鑰。測試網站自己鏡像清冊，不讀正式網站的。
- 兩個環境只差兩個地方：
  - **設定**：用哪一份名冊；測試名冊的平台表多一個 `test-example`。
  - **過卡頁面的建置**：簽的是測試名冊的場合字串 `iamreal-test:public:0`（ADR-0007）。其他和正式的建置相同，取捨和本機用真卡片的建置一樣（`web/README.md`）。

兩個環境各有一把只能部署自己那個 Worker 的權杖（ADR-0029）。

## 只收真卡片

測試網站只認內政部的發證金鑰，和正式網站相同。後台認哪些發證金鑰寫死在程式裡，不做成設定值。假卡片只用在本機和 CI：假的發證金鑰每次測試當場產生，私鑰不留下。

## 誰進得去

全部開放：過卡頁面、訪客的頁面、名冊和清冊的下載。不宣傳；每一頁標「測試名冊」，加 `noindex`。

- 頁面：`test.iamreal.tw`
- 名冊和清冊：`test-data.iamreal.tw`，目錄照 ADR-0027 的排法。`iamreal-verify` 換網址就能重驗測試名冊。

連線紀錄、限流和正式網站相同（ADR-0022、ADR-0026），用同一份隱私權說明。

## 清空

測試名冊不定期清空，只在兩種情況下清：規則或紀錄的格式改了、舊的測試紀錄照新規則讀不懂；或要從空的名冊試某種狀況。每一頁的「測試名冊」標示旁邊寫上次清空的日期。

只有營運者能清。做法是改測試環境的設定（換一個新的 Durable Object 名稱、清空測試的 R2 儲存桶）再重新部署。Worker 裡沒有任何清空名冊的介面。

## 重驗和指紋檔

每天的重驗（ADR-0025）對測試名冊也跑一份。沒通過時只通知營運者，不停收過卡、不開公開的 issue。清空之後重驗從頭開始。

測試名冊的指紋檔不抄到 `iamreal-tw/fingerprints`（ADR-0027）。

## 理由

- **營運者只有一個人。** 封閉試用、預演、上線後的測試共用一個網站，要顧的只多一份。三種用途有衝突：預演要常常換新版，試用的人要穩定。選擇讓試用的人先碰到新版的問題，這正是預演要抓的。
- **預演跑的就是正式的程式。** 兩個環境只差名冊和場合字串，所以清冊鏡像、限流、快取、寫入在測試網站上看到的行為，就是正式網站的行為。ADR-0026 裡幾件文件查不到、要實際看的事，就在這裡看。
- **後台的發證金鑰不能是設定值。** 只要正式網站可能因為設錯而收下假卡片，名冊上「每一張卡片都是內政部發的」就要多相信一份設定。收假卡片還要長期保管一把假的發證金鑰，鏡像也要多收它簽的假清冊。代價是沒有讀卡機的人試不了網頁版；手機 app 的測試者本來就要用真卡片。
- **訪客的頁面一定要開放。** 封閉試用要試的，包括島民證明放在 Threads 的個人檔案上、陌生人點進來看。過卡頁面的程式本來就看得到；有人把島民證明放上個人檔案，這個專案就被看見了。所以「不宣傳」不等於「保密」，擋住過卡頁面換不到什麼。
- **清空不能是 Worker 的一個介面。** 有了這個介面，正式網站上也會有一段能刪掉整份名冊的程式，就算加了密碼也一樣。
- **網址是一層的子網域。** Cloudflare 的 Universal SSL 憑證只涵蓋根網域和第一層的子網域（[Universal SSL limitations](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/)），所以不用 `data.test.iamreal.tw`。

## Considered Options

- **一個 Worker 照網址分兩份名冊**：ADR-0023 的「一份名冊一個 Durable Object」容得下。但兩份一起部署，測試的那一份出錯，正式的跟著停，預演就沒有意義了。
- **另一個 Cloudflare 帳號**：金鑰完全分開，但要另外開付費方案、多維護一份設定。金鑰靠只能部署一個 Worker 的權杖分開（ADR-0029）。
- **真卡片和假卡片都收**：沒有讀卡機的人也能試，CI 也能對部署好的網站跑端到端測試。沒有採用，理由見上面「後台的發證金鑰不能是設定值」。
- **過卡頁面擋在 Cloudflare Access 後面，只讓受邀的人進**：要收試用者的 email，手機 app 和指令要另外帶權杖。測試網站前面也會多一層，快取和限流的行為就和正式網站不同。
- **另買一個網域給測試網站**：和正式網站分得更開，但要多管一個 zone，WAF 的規則也要另外設，預演就不是同一份設定了。
- **定期清空**：試用的人宣告的帳號會無故消失。只在需要時清，換到的是測試名冊上留著較久的真實使用紀錄。
- **測試名冊的指紋檔也抄一份**：抄的排程發現舊的行變了就會失敗（ADR-0027），而測試名冊一清空，舊的行一定會變。

## Consequences

- **測試網站上的島民證明在清空之後就找不到了。** 試用的人放在 Threads 個人檔案上的連結會連到「找不到」，頁面上的清空日期說明原因。
- **正式名冊開張當天，測試名冊怎麼處理**，跟開張當天的步驟一起決定。
- **隱私權說明要寫明它也適用於測試網站。**
