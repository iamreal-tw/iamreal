# 公開的檔案放在 `data.iamreal.tw`，指紋檔另外抄到獨立的程式庫

紀錄目錄、雜湊清單、指紋檔、卡片狀態檔、清冊存檔放在 `data.iamreal.tw`。這個子網域直接連到 R2 的儲存桶，下載不經過 Worker。網站的頁面留在 `iamreal.tw`。指紋檔另外由一個獨立的公開程式庫每天抄一份。

## 目錄

```
data.iamreal.tw/
  proof-log/
    0000000000000000.jsonl        紀錄目錄，每 1,000 筆一檔
    0000000000001000.jsonl
    fingerprints.jsonl            指紋檔
    hashes/
      0000000000000000.txt        雜湊清單，切法和檔名同紀錄目錄
    card-state/
      2026-11-18.jsonl            卡片狀態檔
  crl/
    index.jsonl                   清冊存檔的索引
    <SHA-256>.crl                 每份清冊的原始位元組
    patches/
      <SHA-256>-<SHA-256>.patch   清冊差異檔：從上一份還原出下一份
  connection-log/
    oldest.json                   連線紀錄裡最舊一筆的日期，和後台看的時間
  count-events/
    oldest.json                   計數的明細裡最舊一檔的日期，和後台看的時間
  count-totals/
    oldest.json                   計數的加總裡最早一天的日期，和後台看的時間
```

- **檔名是這一檔之前的筆數**，寫成 16 位數字，不是這一檔第一筆的序號。序號照舊從 1 開始，指紋檔的筆數照舊等於最後一筆的序號。這樣雜湊清單 `0000000000001000.txt` 開頭附的值，就是指紋檔裡筆數 1000 的那個指紋。
- 路徑不帶版本號：格式的版本寫在紀錄和指紋的算法字串裡。
- 不需要列出目錄。指紋檔最後一行的筆數決定有哪些紀錄檔和雜湊清單；`crl/index.jsonl` 列出有哪些清冊。
- `connection-log/oldest.json` 不是證明紀錄的一部分，重驗用不到它（2026-11-26 加，[#20](https://github.com/iamreal-tw/iamreal/issues/20)）。連線紀錄本身不公開，放在另一個沒有公開網域的儲存桶（ADR-0022）；這個檔只有兩個值：後台每小時去看的時間，和那時最舊一筆連線紀錄的日期。它讓任何人從外面看得出連線紀錄有沒有照說的 31 天刪掉，不用另外開一個要權杖的地方。
- `count-events/oldest.json` 也不是證明紀錄的一部分，重驗用不到它（2026-11-26 加，[#54](https://github.com/iamreal-tw/iamreal/issues/54)）。計數的明細本身不公開，和連線紀錄放在同一個沒有公開網域的儲存桶（ADR-0032）；這個檔只有兩個值：後台每小時去看的時間，和那時最舊一檔明細的日期。它讓任何人從外面看得出計數的明細有沒有照說的 31 天刪掉。
- `count-totals/oldest.json` 也不是證明紀錄的一部分，重驗用不到它（2026-11-27 加，[#435](https://github.com/iamreal-tw/iamreal/issues/435)）。計數的加總本身不公開，和明細放在同一個沒有公開網域的儲存桶，永久保存；這個檔只有兩個值：後台每小時去看的時間，和那時最早一天加總的日期。它讓任何人從外面看得出加總有沒有被到期規則刪掉。
- `crl/patches/` 的清冊差異檔不是清冊存檔的一部分，索引不列它，抄副本時不抄（2026-11-28 加）。內政部每把發證金鑰一天簽 4 份，存檔一天多約 103 MB、一年約 37 GB；同一把金鑰相鄰兩份只差幾十到幾百筆，差異檔約幾 KB。鏡像每補上一份可用清冊的索引行，就從同一把金鑰的上一份可用清冊（照清冊編號）算一份差異檔；檔名是兩份的 SHA-256，從索引相鄰的兩行就推得出來。重驗的人每把金鑰下載第一份整份，之後用差異檔還原，還原出來的 SHA-256 要等於檔名；少了差異檔或對不上，就下載整份。所以差異檔不必相信，格式寫在 `spec/revocation-tree.md`。
- 測試的證明紀錄不放在這個網域。規格只規定目錄裡面怎麼排，不規定網址，所以測試的證明紀錄在自己的網址下用同樣的排法。

## 每天換日時

紀錄檔寫滿就寫到 R2（ADR-0023）。每天台灣時間換日時，Durable Object 依序寫：

1. 還沒寫滿的最後一檔，和它的雜湊清單，蓋掉前一天的那一份
2. 卡片狀態檔
3. 指紋檔加一行

寫完 1、2 才寫 3，所以指紋檔的每一行涵蓋的紀錄都下載得到。最後一檔每天只在後面多幾行，寫滿之後就不再變。

白天下載到的筆數可能比最新的指紋多，因為寫滿的檔不等換日就公開。重驗的人只核對到指紋檔那一行的筆數；多出來的是還沒公布的紀錄。

## 指紋檔的另一份

公開程式庫 `iamreal-tw/fingerprints` 用它自己的排程，每天換日後下載 `data.iamreal.tw/proof-log/fingerprints.jsonl`，確認舊的每一行都沒有變、只在後面多了行，才提交新的行。舊的行變了，就不提交，排程公開失敗。

- 它用那個程式庫自己的權杖，和後台、開發用的程式庫、每天的重驗（ADR-0025）都沒有共用金鑰。
- 不管那天的重驗有沒有通過都照抄。它要固定的是「公布了什麼」，重驗的結果看重驗的執行紀錄。
- 它也在營運者的 GitHub 組織底下，營運者還是能改寫它的歷史。它擋的是「只改一個地方」：要改指紋，得同時改 Cloudflare 和 GitHub 上的兩份；clone 和 fork 過的人手上的舊版會對不上。ADR-0021 寫的「沒有人留著舊的指紋時，營運者能整份重算」，到這一步仍然成立。

## 留多久

紀錄目錄、雜湊清單、指紋檔、清冊存檔永久保留。`connection-log/oldest.json`、`count-events/oldest.json`、`count-totals/oldest.json` 各只有一個檔，每小時整個換掉，不留舊的。卡片狀態檔只留 7 天（ADR-0025），由 R2 的生命週期規則照 `proof-log/card-state/` 刪（[object lifecycles](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)），不靠後台的程式。

規則只需要有紀錄用到的清冊（`spec/revocation-tree.md`），但沒用到的也保留。

## 理由

- **下載不經過後台的程式**（ADR-0023）。R2 的自訂網域連的是一個網域名稱（[public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)）；要放在 `iamreal.tw` 底下的路徑，得由 Worker 讀出來再送。完整重驗要下載整份證明紀錄，每一次過卡都要下載清冊，這些請求不該和頁面、寫入擠在同一套限流和同一個 Durable Object。
- **一天公開一次最後一檔就夠了。** 指紋一天公布一次，更常公開最後一檔，多出來的紀錄，指紋也保證不到。R2 同一個物件一秒最多寫一次（[limits](https://developers.cloudflare.com/r2/platform/limits/)），每寫一筆就更新也不可行。
- **抄到另一家的機器上，不必保管金鑰或付費。** 指紋檔一天一行，放進 git 程式庫，每個 clone 都是一份留存。排程每天都有提交，不會因為程式庫沒有活動被停掉（ADR-0025 的 Consequences）。
- **保留了可以之後再刪，刪了就回不來。** 沒有刪除的程式要寫、要檢查；重驗的人也不必分辨一份清冊是被刪了，還是沒有鏡像到。

## Considered Options

- **`iamreal.tw/proof-log/`、`iamreal.tw/crl/`，由 Worker 讀 R2 再送**：只有一個網域，但每次下載都經過 Worker，和頁面共用限流。
- **R2 給的 `r2.dev` 網址**：Cloudflare 寫明它給開發用、有限流，不適合正式的流量（[public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)）。
- **序號從 0 開始，讓檔名是整數**：筆數和最後一筆的序號會差一，規則、ADR、介面文字裡的「第 1 筆」都要改。
- **指紋只在一檔寫滿時公布**：量少的時候，可能幾週才公布一次。
- **最後一檔由 Worker 從 Durable Object 讀出來給人下載**：違反「下載不經過後台的程式」，讀取會和寫入擠在同一個 Durable Object。
- **指紋檔只放在 `data.iamreal.tw`**：改一個地方就夠了，保證完全靠有人留存。
- **指紋檔寫回開發用的程式庫**：開發的提交會和每天一行的資料混在一起。
- **公開的時間戳記（例如 OpenTimestamps）或每天一筆以太坊交易**：營運者改不了，但重驗的人要多一套工具核對，規格多一段；以太坊還要保管錢包的私鑰、付手續費。這兩種之後可以疊在獨立的程式庫上（例如替它的提交蓋時間戳記），指紋檔和紀錄的格式都不用改。重開的條件：營運轉給組織時，或有人拿具體的用途來要。
- **一週後刪掉沒有紀錄用到的清冊**：存檔比較小，但要多一段判斷和刪除的程式，刪錯了救不回來。清冊存檔大到需要處理時重開。2026-11-28 存檔一年約 37 GB，改用清冊差異檔處理，原檔一份都不刪。
- **清冊差異檔用 zstd 的 `--patch-from`**：差異檔比較小（2026-11-27 的兩對量到 3 到 6 KB），但 Go 的標準函式庫沒有 zstd，重驗的指令要多一個第三方套件，Worker 也要另外包一個 WASM。自己定的格式只有「從上一份複製一段」和「寫入這些位元組」兩種指令，大小在同一個量級，任何語言幾十行寫得完。
- **鏡像一天只收 1 到 2 份清冊**：存檔小 2 到 4 倍，但被廢止的卡多過得了半天，存檔照樣一直長大。
- **只讓營運者每天的重驗快取驗過的清冊**：第一次完整重驗的人照樣要下載整份存檔。

## Consequences

- **過卡的頁面跟 `data.iamreal.tw/crl/` 下載清冊。** R2 的儲存桶設 CORS，只允許 `https://iamreal.tw` 用 `GET` 讀（[CORS](https://developers.cloudflare.com/r2/buckets/cors/)）；過卡頁面的 CSP `connect-src` 加上 `https://data.iamreal.tw`；`docs/api/card-proof.md` 的清冊網址跟著改。裝置本來就用內建的發證金鑰驗每一份清冊的簽章，索引被改最多讓人過不了卡。
- **下載清冊和證明紀錄的請求不經過 Worker，不在連線紀錄裡**（ADR-0022）。隱私權說明照實寫。
- **快取分兩種**：寫滿的紀錄檔和雜湊清單、清冊檔永遠不變，快取很久；最後一檔、指紋檔、索引、卡片狀態檔每天會變，快取要短。
- **`iamreal-verify` 內建預設網址 `https://data.iamreal.tw/`**，有選項可以換成別的網址（測試的證明紀錄、別人架的鏡像）。下載的網址寫在 `cmd/iamreal-verify/README.md`；「怎麼驗證島民證明」的提示詞不改，它只指到那份說明。證明紀錄頁的「下載整份證明紀錄」連到那份說明講下載的一段。
- **`spec/record.md` 要改**：檔名改成這一檔之前的筆數；寫明重驗的人只核對到指紋檔那一行的筆數；指紋檔另外放在哪裡改成指向這一份。`spec/revocation-tree.md` 的「存檔公開在哪裡」也改成指向這一份。
- **抄指紋的排程失敗、沒跑時要有人知道**，和每天的重驗沒有通過一樣，在監控的決定裡定。
- **只有 Worker 透過 binding 寫這個儲存桶；`iamreal-tw/fingerprints` 只有它自己的排程提交**（ADR-0029）。
- **清冊檔在 R2 上鎖成不能刪、不能蓋掉**，紀錄檔不鎖；紀錄目錄和清冊存檔另外抄一份副本到 Cloudflare 以外（ADR-0033）。
