# 憑證證明的電路加上效期檢查

ADR-0001 定的是 PSE 的電路原樣使用。這份提議開一個例外：憑證證明的電路（`certChain`）加一項檢查，確認憑證在過卡當天還沒到期。只改這一處，並且優先讓 PSE 把它收進上游；上游收了，我們就回到釘住上游 commit、原樣使用。

提議的理由是原樣使用時，過期的憑證過得了憑證證明：

- 電路不讀憑證的起訖日。以 commit `97210ba` 為準，`certChain.circom` 檢查的是發證單位的簽章、序號不在廢止清冊、公鑰一致。
- 廢止清冊不涵蓋過期的憑證。內政部憑證管理中心的憑證實務作業基準（v2.1）4.9.3.2 節寫廢止的憑證留在憑證廢止清冊「直至該廢止憑證到期為止」，4.10.1 節寫廢止資訊「須至該被廢止之憑證已過期後始可移除」。所以過期而沒被廢止的憑證不在清冊上，被廢止的憑證過期後也可以被移除。

卡片沒有時鐘，過期後多半仍然能簽章；這一點還沒有用過期的卡片實測。如果成立，後果是：留著的舊卡片各是一個名額；掛失的卡片在憑證過期、從清冊移除後又能過卡。「一張卡片一個名額」和「上次過卡日會停住」這兩件事都會被削弱。

## 做法

- 電路多一個公開輸入：過卡的日期。電路從憑證裡取出到期日，檢查它晚於這個日期。後台檢查這個日期是當天，並且和題目裡的日期一致。
- 到期日的位置要從憑證的結構推導出來，不能只靠持卡人的裝置提供的位置加上位元組的樣子。PSE 的稽核報告（`audit_report_v3.md`）對「取出公鑰」這一步指出過同一類的缺口。
- 場合簽章和宣告碼簽章用的電路（`userSig`）不動，匿名編號的算法不變。
- 連帶要改的：證明金鑰和驗證金鑰、驗證程式（公開輸入多一欄）、瀏覽器端準備輸入的程式。
- 上游沒有收進去時，用公開的分支，和上游的差異只有這一項；對外的說法是「用的是 PSE 公開的電路，加了一項效期檢查」，並指向差異。
- 這項改動要另外請人檢查後才能用在正式的場合字串上。

## Considered Options

- **維持原樣，廢止清冊的快照改成歷來清冊的聯集**：擋得住掛失後過期的憑證，擋不住單純過期的憑證，而且只涵蓋開始存檔之後。
- **維持原樣，只接受目前還在簽發的那一代發證金鑰**：很粗，一代金鑰的簽發期間可能比憑證的效期長。
- **維持原樣，對外不說「有效的憑證」**：說法誠實，但名額的數量不再對應到有效的卡片。

## Consequences

- 被接受之前，ADR-0001 和硬限制照舊；對外只說憑證是「內政部簽發、不在廢止清冊上」，不說「有效」。
- 要先研究改動的複雜度（到期日的位置怎麼從結構推導、約束數量、驗證程式要改多少），再決定接受與否。
- 接受後，ADR-0001 的「一行都不改」改成「只有這一項差異」，檔案雜湊不再和上游的發布相同，要公布自己的雜湊和重現的方法。
- 既然動了電路，會想順便加別的功能。每多一項，「差異一眼看得完」就弱一分；其他改動各自另寫 ADR。
