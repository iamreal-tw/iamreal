# 手機 app 只有一個識別碼；連測試網站的是不上傳商店的開發用 build

> 2026-11-27 由 ADR-0040 取代：改成兩個商店的 app，測試 app 永遠連測試網站。下面是當時的決定，保留作紀錄。

Android 和 iOS 各只有一個商店上的 app，識別碼 `tw.iamreal.app`。這一份取代 ADR-0036 裡「兩個 app」的做法（測試 app `tw.iamreal.app.test` 加正式 app），連帶改掉 ADR-0036 的「誰建置、誰上傳」和「例外：Google Play 的封閉測試」兩段。ADR-0036 其餘的部分（只從 GitHub Actions 上傳、建置和上傳分開、Android 簽章金鑰自己產生、可重現的建置）照舊。

## 一個 app，兩種 build

| | 商店的 build | 開發用 build |
|---|---|---|
| 識別碼（Android、iOS 相同） | `tw.iamreal.app` | `tw.iamreal.app.dev` |
| 連哪裡 | 上線前：測試網站。上線起：正式網站 | 測試網站 |
| 簽的場合字串 | 跟著連的網站 | `iamreal-test:public:0` |
| 發到哪裡 | Google Play 的測試軌道和正式版、TestFlight 和 App Store | 不上傳商店。營運者用線裝；少數測試者：Android 給安裝檔，iPhone 用 Ad Hoc |

- **環境在建置時寫死**，和 ADR-0036 相同。商店的 build 連哪個網站，是程式庫裡的一個設定；上線那一天用一個 PR 改它。
- **上線前每一個商店的 build 都連測試網站**，包括 Google Play 封閉測試的 14 天。這不再是例外。
- **開發用 build 和商店的 build 能同時裝在一支手機上**，因為識別碼不同。上線後要在測試網站試錯誤情況的人用它，不會把手上的正式版換掉。
- **開發用 build 的 Android 簽章金鑰是另一把**，和商店的 app 簽章金鑰無關。
- **商店 app 的 Android 簽章金鑰由營運者保管，不放在 GitHub**，CI 用不到它。ADR-0036 金鑰表上的「離線保管」改成這一句；怎麼保管不寫在 ADR，和 ADR-0036 開頭說的一致。

## 誰上傳、誰發布

| | 做什麼 | 誰 |
|---|---|---|
| 上傳 | GitHub Actions 建置，傳到 Google Play 的內部測試和 TestFlight | 營運者手動觸發；營運者電腦上的 coding agent 也可以觸發 |
| 給測試者 | 把一個 build 推到封閉測試、TestFlight 的外部測試 | 營運者在商店的後台按 |
| 發布正式版 | 把一個 build 升到 Google Play 的正式版、送 App Store 審查 | 營運者在商店的後台按 |
| 標籤 | 升上正式版的 build 的提交，推 `android/v…`、`ios/v…` | 營運者；標籤不觸發上傳，用來讓人找到那一版的原始碼做比對 |

- **CI 的金鑰只能上傳到測試軌道。** Google Play 的服務帳號只有「將應用程式發布至測試群組」；正式版和送審留給營運者手動做，和 ADR-0036 的理由相同。
- **上傳的金鑰放在 GitHub 的 environment `app-test`**，只讓受保護的分支上的工作拿。程式庫已經公開，environment 可以用（ADR-0036 的 Consequences 寫的「公開之前」不再適用）。

## 理由

- **上線前，兩個 app 做的是同一件事。** ADR-0036 已經讓封閉測試跑在 `tw.iamreal.app`、連測試網站；Android 的 `tw.iamreal.app.test` 在上線前沒有用途。
- **iOS 上兩個 app 沒有金鑰的隔離。** 個人帳號能上傳的 API 金鑰碰得到帳號裡所有的 app。
- **兩個 app 唯一換到的，是上線後讓商店的測試者連測試網站、同時留著正式版。** 這件事上線前用不到；上線後少數人用開發用 build 做得到，人多了再開第二個 app。開第二個隨時可以，開了收不回來：上傳過的識別碼刪掉後不能再用。
- **知名的開源 app 都這樣分。** 連測試環境的都是開發用 build，不放進商店；商店的 beta 連正式服務。
- **這個專案上線後不能在正式網站上測。** 過卡會寫進公開的證明紀錄、用掉更換的次數，所以上線後試錯誤情況要連測試網站，靠開發用 build。

## Considered Options

- **兩個識別碼，測試 app 和正式 app（ADR-0036 原本的做法）**：上線後商店的測試者能連測試網站又留著正式版。代價是上線前多一個用不到的 app、兩個識別碼永久佔住，iOS 也沒有因此多一層隔離。
- **一個 app，裡面能切換環境**：一個 build 就能測兩邊，但後台或設定能讓 app 換到別的網站和場合字串，和「環境在建置時寫死」（ADR-0036）相反。
- **一個 app，上線後不留連測試網站的路**：最簡單，但上線後試錯誤情況就只能在正式的證明紀錄裡做。

## Consequences

- **上線後，商店的測試軌道上是下一版正式版，連正式網站。** 測試者在那裡過卡會寫進正式的證明紀錄。
- **上線後連測試網站的人有限。** Android 的安裝檔要測試者自己允許安裝不明來源的 app；iPhone 的 Ad Hoc 每年每種裝置最多 100 台，要先登記裝置。
- **上線當天要改商店 build 連的網站**，並調高測試網站的最低版本（ADR-0035），還連著測試網站的舊 build 在要 PIN 之前停下來。
- **`android/`、`ios/` 現在寫的是 `tw.iamreal.app.test`**，要改成這一份的兩種 build。
- **還沒驗證的**：Google Play 新 app 的第一個 build 能不能用 API 上傳（第三方的說法是要從後台手動傳）；14 天的封閉測試照 app 還是照帳號算。
