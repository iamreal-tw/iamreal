# 紀錄目錄和清冊存檔另抄一份副本，放在 Cloudflare 以外

紀錄目錄和清冊存檔每天抄一份到 Cloudflare 以外的一家物件儲存，叫**副本**（`GLOSSARY.md`）。抄的工作跑在 GitHub Actions，只讀公開的網址，不握 Cloudflare 的任何金鑰。其他的東西都從證明紀錄重算，不抄。正式的證明紀錄收第一筆之前就要有副本。

討論在[備份和還原：正本之外抄一份到哪裡、怎麼重建卡片狀態](https://github.com/iamreal-tw/iamreal/issues/51)。

## 防什麼

| 會發生的事 | 靠什麼 |
|---|---|
| 一個檔被程式的錯蓋掉或刪掉 | 清冊檔鎖住（見下）；紀錄檔靠每天的重驗發現（ADR-0025），從副本換回 |
| 維護者手滑：刪錯儲存桶、生命週期規則的路徑設錯 | 同上；整個儲存桶沒了就從副本還原 |
| 整個 Cloudflare 帳號拿不回來：停權、被盜、付款方式失效 | 副本 |
| 維護者故意改證明紀錄 | 不靠副本。副本是維護者自己的，他改得了正本也改得了副本；這件事靠指紋和別人留存的那一行（ADR-0021、ADR-0027） |

R2 自己的耐久性不是要補的洞：它寫的是一年 11 個 9，資料分散在同一個地理區域的幾個機房，同一頁也寫明這不防刪除（[durability](https://developers.cloudflare.com/r2/reference/durability/)）。R2 沒有物件版本，也沒有複寫到別處的功能（[S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/)）。付款方式失效時 R2 會讀不到，30 天內沒有更新，資料可能被刪除（[billing policy](https://developers.cloudflare.com/billing/understand/billing-policy/)）。

## 抄什麼

| 資料 | 抄不抄 | 理由 |
|---|---|---|
| 紀錄目錄 | 抄 | 掉了補不回來 |
| 清冊存檔 | 抄 | 掉了補不回來；重驗舊紀錄的樹根要它 |
| 指紋檔 | 不另外抄 | 已經有 `iamreal-tw/fingerprints` 那一份（ADR-0027），也能從證明紀錄重算 |
| 雜湊清單、卡片狀態檔 | 不抄 | 從證明紀錄重算 |
| Durable Object 裡的卡片狀態、頁面的衍生表、用過的題目、指紋和筆數 | 不抄 | 從證明紀錄重算（見「從證明紀錄重建」） |
| 還沒用掉的題目 | 不抄 | 持卡人重拿一個 |
| 連線紀錄 | 不抄 | 不公開的個人資料，只留 31 天（ADR-0022）；多一份就多一個要保管、要準時刪的地方。掉了只是那段時間查不了濫用 |

還沒寫滿的最後一檔也抄。它每天換日時在 R2 被蓋掉一次（ADR-0027），副本跟著多一個版本；只抄到指紋檔那一行的筆數為止。

每個檔只抄一次，永久留著。副本的大小等於正本的大小。

## 怎麼抄

- **放在 Cloudflare 以外的一家物件儲存**，私有的儲存桶，開物件版本，並鎖成不能刪、不能蓋掉舊版本。是哪一家寫在工作流程和維護者的說明裡，換一家不用改這一份。
- **GitHub Actions 每天跑一次**，是公開庫裡獨立的一個工作流程。它從 `data.iamreal.tw` 下載新的檔，上傳到副本。做到哪裡看副本裡已經有哪些檔，不靠快取。
- **它拿的身分只能新增和讀副本，不能刪。** 用 GitHub 的 OIDC 向對方換短期的身分，限定這個程式庫、`main` 分支、它自己的 environment；程式庫裡不放長期的金鑰。這個身分被拿走時，對方最多能多塞檔案，已經抄好的動不了；副本的內容本來就是公開的資料。
- **每天的重驗照舊不握任何金鑰**（ADR-0025）。抄副本和重驗是兩個工作流程。
- **當天的重驗有沒有通過都照抄**，和抄指紋檔相同（ADR-0027）。無效的紀錄本來就留在證明紀錄裡（ADR-0014）。

## 怎麼確認副本是對的

1. **抄之前先驗。** 紀錄檔下載後重算每筆紀錄的雜湊，接上前一檔結尾的指紋，要對得上指紋檔。清冊檔的檔名就是它的 SHA-256，重算就知道。對不上就不抄，排程公開失敗。
2. **抄上去的就是驗過的那一批位元組。** 上傳時帶 SHA-256，由對方核對。
3. **每天列一次副本裡的檔**，和指紋檔的筆數、清冊存檔的索引比：該有的都在、大小對。
4. **每天抽幾個檔下載下來重算雜湊。** 它確認的是真的拿得出來、拿出來是對的。

副本不整份定期重查。正本每一檔每 30 天重算一次雜湊（ADR-0025），是因為 Worker 寫得到它、紀錄檔沒有鎖、所有重驗的人都靠它。副本鎖住之後沒有程式改得了；儲存本身的損壞由對方的耐久性處理；要正本和副本的同一檔同時壞才會出事。

## R2 上的鎖

R2 的 bucket lock 讓指定路徑開頭的物件不能被刪、不能被蓋掉，可以無限期，新增不受影響，也蓋過生命週期規則；有權限改儲存桶設定的人可以把規則拿掉（[bucket locks](https://developers.cloudflare.com/r2/buckets/bucket-locks/)）。

- **清冊檔鎖，無限期。** 檔名是十六進位，設 `crl/0` 到 `crl/f` 十六條規則，鎖得到清冊檔，鎖不到每天要改的 `crl/index.jsonl`。
- **紀錄檔不鎖。** 寫滿的檔和每天被蓋掉的最後一檔是同一種檔名，規則分不開。

## 從副本換回一個檔

每天的重驗報某一檔的雜湊變了（ADR-0025），或某一檔不見了：

1. 從副本下載那一檔，用 `iamreal-verify` 重算雜湊，對得上指紋檔（清冊檔是對得上檔名）才往下。
2. 維護者臨時做一把只能寫這個儲存桶的權杖，上傳蓋掉，刪掉權杖。
3. 再跑一次重驗，確認正本那一檔對了。
4. 開公開的 issue。

不停止收過卡。這是 ADR-0029「R2 只有 Worker 透過 binding 寫」的例外，也是可以不經過 Actions 的第三件事。

## 從證明紀錄重建

後台有一個步驟「從證明紀錄重建」：把 Durable Object 裡所有從證明紀錄算得出來的東西重算一遍。包括每張卡片的狀態、頁面的衍生表、用過的題目、指紋和筆數。

- **三種情況都用它**：卡片狀態檔和重算的不同、紀錄規則的版本號加了一號（ADR-0025）、Durable Object 的資料沒了。沒有「只重建卡片狀態」的版本。
- **在 Durable Object 裡用 TypeScript 的規則算**，照每一筆紀錄的日期選規則的版本（ADR-0031）。讀 R2 上的紀錄檔，加上自己手上還沒寫到 R2 的紀錄，分批做。
- **先算進新的表，全部算完才在一個交易裡換過去。** 中途失敗，舊的還在。
- **做的期間停止收過卡**，頁面照常用舊的表。
- **由維護者觸發**，和停止收過卡相同。

重建完，兩個條件都過，維護者才手動恢復收過卡：

1. **後台自己核對**：算出的筆數和指紋，和指紋檔最後一行相同。不同就不換表。
2. **Go 的重驗比過**：重建完立刻寫一份卡片狀態檔，維護者手動觸發一次重驗的工作流程，逐張比過。

要多久在測試網站量。

## 搬離 Cloudflare

**自己決定要搬**：

1. 停止收過卡，等到換日那一次寫完（最後一檔、卡片狀態檔、指紋檔的那一行）。這時每一筆紀錄都在檔案裡。
2. 把紀錄目錄、雜湊清單、指紋檔、清冊存檔抄到新的地方。
3. 在新的地方從證明紀錄重建，照上面兩個條件核對。
4. 把網域指過去，恢復收過卡。

**帳號拿不回來**：

1. 從副本拿紀錄目錄和清冊存檔，從 `iamreal-tw/fingerprints` 拿指紋檔。
2. 用 `iamreal-verify` 從第 1 筆整份重驗，確認副本對得上指紋檔。
3. 從證明紀錄重建、核對、恢復，同上。
4. 公告：最後一次換日之後的過卡要重做。

兩種情況用的都是公開的那幾種檔案和「從證明紀錄重建」，沒有只為搬家寫的程式，也沒有只有維護者才有的資料。還沒用掉的題目丟掉，連線紀錄不搬。

## 處理的步驟寫成文件

`docs/playbooks/` 一種狀況一個檔：換回一個檔、從證明紀錄重建、搬到別的地方、帳號拿不回來、抄副本的排程失敗。每個檔寫什麼時候用、動手前先確認什麼、步驟、怎麼確認做完、之後要開的 issue。

每一步標明誰做。coding agent 可以下載公開的檔、跑 `iamreal-verify`、比對、起草 issue；Cloudflare 的儀表板、臨時的權杖、停止和恢復收過卡、副本那一家的後台只有維護者做（ADR-0029）。

抄副本的工作流程對測試的證明紀錄也跑一份，抄到另一個儲存桶；那個桶不鎖，因為測試的證明紀錄會清空（ADR-0028）。正式的證明紀錄開張之前，每一份文件在測試網站走過一次。

## 理由

- **要防的三件事裡，帳號拿不回來只有放在別家才防得到。** 同一個帳號裡的第二個儲存桶擋得住程式的錯，擋不住這一件。
- **抄的工作不握 Cloudflare 的金鑰，Cloudflare 裡也不放副本的金鑰。** 一邊出事時，另一邊不受影響。讀公開網址的做法和重驗、抄指紋檔相同。
- **副本的用處在沒有人刪得掉。** 所以身分只能新增、儲存桶鎖住，抄錯的機會留在上傳之前擋。
- **能算出來的不抄。** 要抄、要核對的只有兩種檔；還原出來的東西和外面任何人拿公開的檔算出來的相同。
- **一條重建的路。** 三種情況走同一個步驟，平常少用的程式不會各自壞掉；每次重建都由另一份實作比過。
- **維護者只有一個人**（ADR-0023）。排程每天自己跑；出事時照文件做，不靠記憶。

## Considered Options

- **先不做，等用量大了再說**：副本晚加不用改任何格式。沒有採用，因為證明紀錄從第一筆起掉了就補不回來，而手滑和設定錯最容易發生在剛上線、設定還在改的時候；一個人營運，「用量夠大」那一天沒有人提醒。
- **第二份放在同一個或另一個 Cloudflare 帳號的 R2**：最省事。Cloudflare 對維護者或這個服務採取行動時，兩邊可能一起出事。
- **放 GitHub Releases**：免費，總量沒有上限，但一個 release 最多 1,000 個檔（[about releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)），要多一層打包和編號；重驗、指紋檔的另一份、程式都已經在 GitHub。
- **放維護者自己的電腦或硬碟**：要靠人記得做。
- **R2 的物件建立事件觸發一個 Worker 去抄**：副本的金鑰要放在 Cloudflare 裡，帳號出事時一起落到別人手上。
- **每 30 天把副本整份下載重查**：重做對方已經在做的事，而且讀出來要付流量費，副本越大越貴。
- **把最後一檔搬到另一個路徑，讓紀錄檔也能鎖**：要改 ADR-0027 的目錄和 `spec/record.md`，每個重驗的人都要跟著改。紀錄檔壞掉本來就會被重驗發現、從副本換回，差別只是晚一點知道。
- **當天的紀錄寫入時同步寫到 Cloudflare 以外**：能補上「最後一天會掉」，但過卡多依賴一家、多一種失敗。
- **在外面用 Go 算好卡片狀態再傳進後台**：後台要開一個收狀態的入口，外面的工作要握能寫後台的金鑰；而且每天的比對是拿 Go 算的去比後台存的，後台存的也是 Go 算的，就比不出東西。
- **Worker 開一個維護者專用的入口，自己去副本拿檔來換**：Worker 要握副本的讀取金鑰，多一個要保護的入口，為的是可能幾年不發生一次的事。
- **連線紀錄也抄**：見「抄什麼」。

## Consequences

- **整個帳號拿不回來時，最後一次換日之後的過卡會掉。** 當天的紀錄只在 Durable Object 裡，換日才寫到 R2（ADR-0027），再過一次排程才到副本。這些紀錄還沒被任何一天的指紋涵蓋（ADR-0021），但持卡人看過完成的畫面，要重新過卡一次。只是 Durable Object 自己的資料出問題時，它可以回到過去 30 天內的任一時點（[SQLite storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)），不走這一條。常見問題照實寫這件事；那一句寫進 `design/copy/` 時另外給維護者看。
- **多依賴一家服務商，多一個帳號要顧。** 那個帳號的登入照 ADR-0029「帳號」那一層：維護者本人，實體安全金鑰。它付款失敗或排程拿不到身分時，每天的排程會失敗；通知和重驗沒有通過的一起做（[#53](https://github.com/iamreal-tw/iamreal/issues/53)）。
- **GitHub 上多一個拿得到身分的工作流程。** 它照 `CONTRIBUTING.md`「部署會執行到的東西」審：action 釘在完整的 commit SHA，只由排程和手動觸發。
- **GitHub 停擺時副本會晚幾天。** 恢復後接著抄，沒有東西掉；正本和 GitHub 同時出事才有損失。
- **清冊檔鎖了之後，測試和正式的 R2 上都刪不掉清冊檔**，除非先拿掉規則。清空測試的證明紀錄時不清清冊存檔。Worker 透過 binding 的寫入會不會被擋、清冊鏡像重抓到同一份清冊時會不會因此失敗，文件沒有寫，在測試網站確認。
- **換回一個清冊檔要先拿掉它那一條規則，換完加回去。** 寫在文件裡。
- **`iamreal-verify` 要能只重算一個檔的雜湊並和指紋檔比**，給「換回一個檔」和抄副本的工作流程用。ADR-0025 的「指定一段序號」已經接近，施工時確認。
- **後台要有「從證明紀錄重建」和它的觸發方式**，跟停止收過卡的機制一起做。
- **抄副本的排程每天都有執行紀錄，但不提交東西。** 公開的程式庫 60 天沒有活動時排程會被停掉（ADR-0025）；開發停下來的期間要留意。
