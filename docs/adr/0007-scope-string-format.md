# 場合字串的格式

場合字串是卡片第一次簽的那段字，匿名編號由它的簽章算出。電路要求它剛好 31 個位元組，第一個字元符合下面的種類規則（ADR-0013），其餘內容不限。我們自己經營的場合用人看得懂的 ASCII 字串。公開名冊只有一個場合，所有公開平台共用（ADR-0017）：

```
iamreal:public:0_______________
```

| 部分 | 規則 |
|---|---|
| 名字 | 固定是 `iamreal` |
| 範圍 | 小寫英文字母、數字、連字號，最長 21 個字元。公開名冊是 `public` |
| 版本 | 十進位數字，從 `0` 開始 |
| 分隔 | 三個部分之間用 `:` |
| 補滿 | 後面用 `_` 補到 31 個位元組 |

`:` 和 `_` 不會出現在名字、範圍和版本裡，所以一段場合字串只有一種拆法。

這是上線後唯一完全在我們手上、又改不了的東西：改了，每張卡片的匿名編號都會變，已經用掉的名額全部失效。所以裡面只放永遠不變的東西。

- **不放網域。** 網域可能更換；寫進去也擋不住釣魚，假網站可以要求卡片簽一模一樣的字。
- **平台不放在場合字串裡**（ADR-0017）。平台代號是紀錄上的欄位，也寫進宣告碼。它是永久的識別碼，不是顯示名稱：取平台當時最通用的英文名稱，定了就不改，平台改名也不跟。顯示名稱放在平台的資料裡。
- **版本只在整個場合要作廢重來時才升。** 升了之後新舊匿名編號對不起來，舊版本的名冊封存、不再接受新事件，所有持卡人重新宣告。正常情況下永遠是 `0`。
- **名字不用通用的縮寫。** 別的專案用同一份電路、同一段字時，同一張卡片在兩邊的匿名編號會相同。

## 第一個字元決定種類

卡片簽的每一段字都是 31 個位元組，在卡片看來長得一樣。規則是看第一個字元的大小寫，由電路檢查（ADR-0013）：

- **小寫開頭**：人看得懂的場合字串，就是上面的格式。
- **大寫開頭**：算出來的字串，第一個字母說明種類。`S` 保留給其他服務自己開的場合，內容是服務的登記資料的雜湊；算式在第一個服務接入之前另外定。`D` 和 `R` 是卡片第二次簽的代碼（ADR-0002），格式另外定。其他大寫字母保留。

## 測試用的場合字串

測試和封閉試用用另一個名字：`iamreal-test:public:0`，同樣補到 31 個位元組。它產生的匿名編號和正式的無關。不用版本號區分測試和正式，版本號只有上面那一個意思。

## Considered Options

- **全部用雜湊**（我們自己的場合也是 `S` 開頭）：格式只有一種，內容長度不限。但看到證明的人要查登記資料重算，才知道它屬於哪個場合；雜湊前的內容怎麼組（哪些欄位、順序、編碼）一旦有人用就不能改，等於把一個可以晚點定的決定提前。可讀字串本身就是全部，沒有會做錯的地方。
- **全部用可讀字串**：其他服務的場合要包含它的網域才不會互相冒用，31 個位元組放不下。
- **格式含網域**（`<網域>:<平台>:<版本>`）：見上面「不放網域」。

## Consequences

- 可讀性保護不了持卡人：簽章當下沒有人會讀這 31 個位元組。它的用處在事後，任何人拿到一份證明，不查任何登記表就知道它屬於哪個場合。
- 能讓卡片簽這段字一次的人，算得出這張卡片的匿名編號（ADR-0004）。格式怎麼定都擋不住。
- 這份格式在正式的場合字串啟用之前，要請懂密碼學的人看過；在那之前狀態是 proposed，封閉試用用測試的場合字串跑。
