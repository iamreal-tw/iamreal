# 憑證證明的電路只認國民的正卡

憑證證明的電路（`certChain`）加一項檢查：憑證必須是簽發給國民的正卡憑證。附卡、行動自然人憑證、外來人口的自然人憑證都過不了卡。這是 ADR-0008、0009、0010 之後的第四項電路差異，符合 ADR-0001 的「只加檢查」。

## 為什麼

名額要算的是一個人，不是一張憑證。

內政部的憑證格式（《政府機關公開金鑰基礎建設憑證及憑證廢止清冊格式剖繪》第 2.4 版，1.3.18 和 1.3.19 節）在主體目錄屬性（`subjectDirectoryAttributes`）這個延伸欄位裡記了兩件事：

- **載具。** 選用的屬性 `cardHolderRank`：`secondary` 是附卡，`mobile` 是行動載具（行動自然人憑證）。沒有這個屬性的是正卡。
- **身分類別。** 屬性 `subjectType`：國民和外來人口是兩個不同的代號。

附卡和行動自然人憑證各有自己的金鑰和簽章用憑證。上游的電路不看這個欄位，所以一個人有幾張簽章用憑證，就有幾個匿名編號。

我們本來就不支援行動自然人憑證（簽章要經過內政部的伺服器）。但算證明的程式在持卡人的裝置上，電路只看憑證和簽章，不看它們怎麼來的。這項檢查讓「不支援」由證明保證，而不是由我們的程式保證。

這不是假想的情況。上游的 iOS 範例（[openac-taiwan-citizen-digital-certificate-ios-example](https://github.com/privacy-ethereum/openac-taiwan-citizen-digital-certificate-ios-example)）就是從內政部的行動自然人憑證服務取得憑證和簽章，再用同一份憑證證明的電路算證明。內政部的憑證查詢系統也顯示，行動自然人憑證是另外簽發的一組憑證，其中一張的金鑰用途是簽章，序號和實體卡的不同（2026-11-15 查詢）。

### 為什麼只收國民

持有居留證的外來人口也能申請自然人憑證（內政部憑證管理中心的憑證實務作業基準 4.1.1）。上游的電路兩種都收。我們只收國民，理由是：

- **第一個場合的用途是公共討論。** 在那裡，名額代表的是「這個社會裡有一個人」。設籍的國民是一條明確、查得到的界線。
- **居留是有期限的。** 居留結束後，憑證對本人不再有用，但在廢止之前仍然能過卡。作業基準規定移民署通知居留證註銷時廢止憑證；這個通知多快、多確實，我們沒有查證。
- **之後可以放寬，反過來很難。** 匿名編號是簽章的電路算的，那份電路不動。之後要對某個場合開放外來人口，換憑證證明的電路和金鑰就可以，已經宣告的名額不受影響。先收再收緊，已經宣告的名額就要處理。

這條線畫的是法律上的資格，不是出身：已經設籍的歸化國民是國民；長期居留但沒有設籍的人不是。

## 做法

- ADR-0010 已經走到金鑰用途。這裡接著往下走兩個延伸欄位：憑證政策，然後是主體目錄屬性。
- 國民的正卡憑證，這兩個欄位共 75 個位元組，長度和內容都固定，只有最後 4 個位元組（身分證字號的末四碼）因人而異。
- 電路把前 71 個位元組釘死：憑證政策是內政部第 3 級保證等級的那一個（`2.16.886.101.0.3.3`）；主體目錄屬性剛好兩個屬性，依序是 `subjectType` 等於國民、身分證字號末四碼。末四碼的內容不看。
- 主體目錄屬性的長度被釘住之後，沒有地方放 `cardHolderRank`，所以不需要去找它。
- 場合簽章和宣告碼簽章用的電路（`userSig`）不動，匿名編號的算法不變。

釘死的位元組用兩張卡片核對過（2026-11-15）：一張現役的正卡（G3 發證金鑰簽發）和一張過期的舊卡（G2 發證金鑰簽發）。兩張的簽章用憑證在這個位置的 71 個位元組都和電路預期的完全相同。

## 量測

用 circom 2.2.3 編譯（2026-11-15）：

| | 上游 `97210ba` | 到 ADR-0010 為止 | 再加這一項 |
|---|---|---|---|
| `certChainRS2048` 的約束數量 | 1,841,657 | 1,848,532 | 1,848,532 |
| `certChainRS4096` 的約束數量 | 2,033,081 | 2,039,956 | 2,039,956 |

約束數量沒有增加。新加的約束都是「這個位元組等於某個常數」，編譯器最佳化時把它們代換進其他約束，不單獨計數。下面的測試是用較低的最佳化等級（`--O1`）編譯的電路跑的。正式的等級（`--O2`）另外做了獨立的檢查：把這兩個模板單獨編譯成小電路，拿竄改過的見證直接驗約束。外來人口、`mobile`、`secondary`、屬性換位置、尾碼換型別或長度、憑證政策不同，都被約束擋下；75 個位元組逐一翻位元，只有最後 4 個不受約束。這次檢查沒有重新編譯完整的電路。

測試：國民的正卡憑證通過，末四碼換成別的值也通過。被拒絕的有：帶 `cardHolderRank` 等於 `mobile` 或 `secondary` 的憑證（放在其他屬性之前或之後都一樣）、外來人口的憑證、其他身分類別、兩個屬性順序對調、憑證政策不同、沒有主體目錄屬性、兩個延伸欄位順序對調、中間多一個延伸欄位、在主體目錄屬性中間截斷的憑證。

## Considered Options

- **不改電路，由讀卡的程式只讀正卡**：讀卡的程式在持卡人的裝置上，持卡人可以換掉。
- **兩種身分類別都收**：和上游一致，能用的人多約 5%。但「一個名額代表什麼」會變成「合法居留在台灣的成年人」，而且居留結束後的憑證是不是及時廢止，我們沒有把握。
- **多一個公開輸入，由場合決定收不收外來人口**：最有彈性，約束幾乎不增加。但現在只有一個場合，多一個沒有人用的參數，就多一項要寫進規格、要請人檢查、要向使用者解釋的東西。等有第二種場合需要時再做。
- **在主體目錄屬性裡找 `cardHolderRank`，找到才拒絕**：不依賴欄位的長度，但電路複雜很多，也擋不住身分類別。

## Consequences

- 一個人只有正卡那一張憑證能過卡。持卡人不受影響：過卡用的本來就是正卡。
- **持居留證的外來人口過不了卡。** 這是有意的限制，對外要說清楚：名額代表的是「一張國民的自然人憑證正卡」。
- 對外的用詞不能比證明的多。這項檢查證明的是憑證的身分類別，不是居住地（移居海外的國民卡片仍然有效），也不是出身。
- **這項檢查靠的是內政部照格式文件簽發。** 我們沒有看過真的行動自然人憑證或附卡（已向上游的維護者詢問）；內政部簽發時如果沒有寫 `cardHolderRank`，這項檢查擋不住。
- 憑證政策的代號、延伸欄位的順序、主體目錄屬性的內容，任何一項改變，新格式的卡片都過不了卡，電路要跟著改。格式文件明寫延伸欄位「實際在憑證中的順序可能不是照以下的順序」，所以我們依賴的順序是觀察到的，不是規格保證的。上線前要用更多不同年份的卡片核對，目前只核對過兩張。
- 身分證字號的末四碼在憑證裡，電路讀得到但不輸出，也不檢查。
- 這個問題上游也有。回報的時機另外決定。
