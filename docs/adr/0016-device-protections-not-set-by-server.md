# 持卡人裝置上的保護，不由伺服器決定

一條限制如果是在保護持卡人、對抗伺服器，就寫死在持卡人的裝置上。伺服器可以讓它更嚴，不能讓它更寬。

伺服器在這個系統裡能做很多事：發題目、提供清冊的鏡像、收證明、寫證明紀錄。持卡人的匿名性不能依賴伺服器守規矩（`CLAUDE.md` 的硬限制：匿名編號只有持卡人算得出來）。凡是「伺服器給了不同的值，就能知道持卡人是誰，或把他在不同場合的身分連起來」的地方，那個值都要由裝置自己決定或自己檢查。

## 目前用到的地方

| 限制 | 伺服器能決定的話，會怎樣 | 裝置怎麼做 |
|---|---|---|
| 卡片簽哪個場合字串 | 讓卡片多簽另一個場合的場合字串（例如其他服務的場合），就拿到持卡人在那個場合的匿名編號，把他在公開的證明紀錄裡的帳號和那個場合裡的身分連起來 | 場合字串寫死在程式裡（`spec/scope.md`），不從伺服器的回應裡拿；畫面沒有選場合的地方 |
| `current_time` | 伺服器挑時間，每次過卡問「憑證在這個時刻有沒有效」，約 28 次就能二分出憑證的生效時刻到秒，內政部能據以對到人 | 裝置用自己時鐘的台灣日期；題目上的日期不是今天就不過卡（`spec/challenge.md`） |
| 廢止清冊多舊還能用 | 鏡像給某人一份舊清冊，從他過不過得了卡，知道他的卡那時是否暫時停用過 | 取伺服器公布的天數和內建 7 天中較小的，並記住看過的最高清冊編號（ADR-0015） |
| 廢止清冊的樹 | 樹裡多塞幾個嫌疑人的序號，從過不過得了卡指出持卡人 | 裝置自己驗內政部的章、自己建樹（ADR-0015） |
| 什麼時候向後台查這張卡片的現況 | 查現況會把匿名編號交給後台。卡片在鏡像給的清冊上時，後台看到「這個匿名編號查過、之後沒有下文」，就知道這張卡那時被廢止或暫時停用，內政部知道那是誰 | 不需要簽章就能做的檢查全部通過，才要第一次簽章：憑證、清冊的章、建樹、序號不在樹裡。過不了的卡不會產生匿名編號，後台看不到是哪一張卡片。停在哪一步和錯誤代碼會當成計數送出，裡面沒有匿名編號（ADR-0032） |
| 平台的顯示名稱和帳號的寫法 | 把代號 `threads` 顯示成另一個服務的名稱，持卡人會把帳號宣告在他沒有打算宣告的平台上，公開之後收不回來 | 寫死在裝置上。伺服器給的平台表只決定哪些平台現在可以填、帳號名稱的格式；確認的畫面列出整份要簽的清單（ADR-0019） |
| 裝置不認得的平台上的帳號 | 一筆紀錄是整份清單，少了一個帳號就是收回它。伺服器回的現況少報一個帳號，或裝置把不認得的平台丟掉，持卡人就在不知情的情況下收回了它 | 原樣放回清單，顯示成不能修改的一列；確認的畫面列出會被收回的帳號（ADR-0019） |
| 跑哪一份電路、用哪一份參數檔 | 電路同時看得到憑證、公鑰和兩個簽章。伺服器給一份改過的電路，就能把憑證序號放進公開輸出，跟著證明送出去 | 電路檔、驗證金鑰、參數檔的 SHA-256 寫死在裝置上，用之前核對，不同就停，在卡片簽章之前（網頁版：`web/src/prover/artifacts.ts`；app：ADR-0035） |
| 這一版 app 還能不能過卡 | 紀錄規則內建在 app 裡。規則改了之後，舊版顯示的後果可能和證明紀錄實際算的不同，持卡人照錯的後果同意，公開之後收不回來。伺服器能做的只有叫裝置停，不能叫它照別的規則算 | 裝置讀伺服器公布的最低版本和起算日，自己太舊就在要 PIN 之前停下來。這個值對每個人都一樣，只會讓裝置更嚴（ADR-0035） |
| 卡片的一組簽章算幾次證明 | 卡片的簽章是固定的，裝置留著它們，不需要卡片和 PIN 就能一直重算證明。算證明的輸入如果被別人決定了，又看得到算不算得出來，每算一次就是對這張憑證問一個問題；失敗後自動換輸入再算，一次過卡就能問完（每次問一半的候選序號，100 萬張卡約 20 次） | 一組簽章只算一次證明。算不出來就停下，簽章不留；要再試得重新拿題目、重新簽章（要 PIN）。伺服器的回應不會讓裝置自己再算一次。送出沒有回應時重送同一份證明不算（`spec/device-checks.md`「One proof for the card's signatures」） |

過卡失敗的原因顯示給持卡人。停在哪一步和錯誤代碼另外當成計數送給後台，用來找出流程哪裡該改；計數裡沒有匿名編號、帳號和卡片上的任何內容（ADR-0032）。計數的明細留 31 天，裡面沒有 IP（ADR-0032）；明細帶著過卡裝置編號（ADR-0039），所以這段期間後台看得出有一台裝置有一張卡片因為被廢止或暫時停用而過不了卡，看不出是哪一張，也看不出是從哪個 IP。

連線紀錄記了什麼、留多久，見 ADR-0022。

## app 在手機上留下什麼

app 過完卡之後，手機上只留提醒過卡用的四樣東西：提醒開著還是關著、持卡人選的間隔、提醒的時刻、下次提醒的日子。持卡人選好提醒的間隔和時刻、按了「開啟提醒」才會存（過卡第 7 步的「設定提醒」和設定頁的開關都打開那一頁）；關掉提醒就刪掉。

不留的：PIN、憑證和它的任何欄位、公鑰、簽章、匿名編號、短編號、帳號、島民證明的連結、上次過卡日。

提醒由手機自己排，不經過伺服器。伺服器來發通知的話，就要記住哪一支手機對應哪一張卡片。

拿到解鎖手機的人看得出這支手機過過卡、下次提醒是哪一天，看不出是哪一張卡片、宣告了哪個帳號。app 不記卡片，所以同一支手機可以過不同人的卡，提醒只有一個。

## 代價

- **原生 app 要使用者手動更新。** 寫死的規則要等更新才會改，所以之後可能放寬的限制，裝置一開始就訂寬一點，放寬時只動伺服器和規格（ADR-0015 的 7 天就是這樣訂的）。要收緊時，舊版 app 照樣會做出伺服器會拒絕的證明，那是看得到的失敗，不會害到持卡人。紀錄規則不是這樣：舊版照舊規則顯示的後果，伺服器不會拒絕，所以太舊的 app 讀到最低版本後自己停（ADR-0035）。
- **網頁版的頁面也是伺服器送的。** 頁面和 API 從同一台伺服器來時，這條原則擋不住營運者本人：改過的頁面可以照它想要的方式做。它擋得住的是 API 被入侵、或之後頁面和 API 分開部署時的其中一邊；它也讓公開的 `web/` 程式碼看得到這些規則。對外說「營運者算不出匿名編號」時，網頁版的前提是用的頁面就是公開的那一份；原生 app 的前提是安裝的是公開程式碼編出來的那一版。

## Considered Options

- **伺服器在回應裡告訴裝置要用什麼值**（場合字串、時間、清冊的上限）：最有彈性，但這些正是伺服器拿來探測持卡人的工具。
- **裝置照伺服器的值，但事後由重驗的人檢查**：探測不需要成功的證明，失敗的過卡不會留在證明紀錄裡，重驗的人看不到。

## Consequences

- 寫裝置上的程式（`web/`、`android/`、`ios/`）時，每一個從伺服器拿到的值都要問：伺服器換一個值，能不能藉此知道持卡人是誰，或讓他公開一件他沒有要公開的事？能的話，就照這份決定處理。
