# 名冊是只增不改的事件流水帳，現況由公開規則算出

名冊只存事件，不存現況。事件有兩種，都附證明：宣告和收回。一個帳號現在有沒有被宣告、一張卡片現在宣告的是誰、更換過幾次，都是拿整份名冊照一份公開的規則算出來的。API 只是捷徑：任何人下載快照自己重算，要得到和 API 一樣的答案。

理由：

- **一份證明只證明「當下這個動作」。** 「這張卡片現在宣告的是誰」要把同一個匿名編號的所有事件依序串起來才知道，所以現況沒有辦法直接附證明。存事件，每一筆才都是可以重驗的。
- **規則公開，營運者就沒有裁量的空間。** 一張卡片一個名額、更換的次數上限、收回，都寫成規格和參考實作，照著算就有答案。
- **規則可以調整，事件不用動。** 例如更換的次數上限之後要收緊，改的是規則，已經寫入的事件不受影響。

## Considered Options

- **存現況（一張「帳號對應卡片」的表），另外留紀錄**：查詢簡單，但表裡的內容是營運者算好的結果，外人只能相信。
- **事件種類分細**（第一次宣告、再次過卡、更換各一種）：它們在證明上是同一件事，差別只在帳號名稱和上一次是否相同，由規則分辨就夠。

## Consequences

- 名冊不設到期日。它只記事實和日期，多新的宣告才算數由查詢方和顯示的一方決定；API 的回應一定帶日期，不提供單純的「是或否」。
- 名冊不記卡片序號，所以營運者沒有辦法主動檢查某張卡片的憑證是否已被廢止。這不是還沒做，是做不得：廢止清冊列的是憑證序號，任何能從序號對到匿名編號的方法，發證單位也能拿來查出每個人的匿名編號。廢止只在持卡人過卡的時候檢查，因此上次過卡日是判斷新舊的核心依據。
- 公開的日期只精確到日。
- 名冊上每一筆事件都附證明，不提供刪除。持卡人能做的是收回。拿掉帳號和匿名編號的對應也刪不掉：宣告碼和題目都公開，把帳號名稱代進去算就找得回來。沒有證明的刪除事件，則任何人冒充持卡人都能讓一筆紀錄消失。帳號主人要求時，之後發布的名冊隱去那個帳號名稱，並公開記下隱去了哪一筆。
- 每一筆紀錄帶著前一筆的雜湊，串成一條鏈（`spec/record.md`）。只要有人保存過舊的鏈尾雜湊，營運者就不能偷偷拿掉一筆、調換順序，或對不同的人給出不同的名冊。每日快照連同鏈尾提交到公開的 git 程式庫，任何人都能 clone、留著看過的鏈尾。這要靠有人留存：營運者仍然能改寫自己的 git 歷史，或給不同的人看不同的快照，只有留著舊版的人會發現。上線時不另外交給第三方（例如寫進公開的區塊鏈）；之後要加，不必改紀錄的格式。
