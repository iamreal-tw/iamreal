# 證明紀錄是只增不改的事件流水帳，現況由公開規則算出

> Consequences 最後一條原本的做法（每筆紀錄帶前一筆的雜湊、串成一條鏈）由 ADR-0021 取代。上線之後改規則要守的條件在 ADR-0031。其餘有效。

證明紀錄只存事件，不存現況。事件只有一種，都附證明：一次過卡一筆紀錄，寫著這張卡片當下的整份帳號清單（ADR-0017）。宣告、收回、更換、更正、再次過卡不是不同的事件，是規則拿這一份清單和這張卡片前一份清單比對出來的結果，每個平台各算。一個帳號現在有沒有被宣告、一張卡片現在宣告的是哪些帳號、每個平台更換過幾次，都是拿整份證明紀錄照一份公開的規則算出來的。API 只是捷徑：任何人下載快照自己重算，要得到和 API 一樣的答案。

理由：

- **一份證明只證明「當下這個動作」。** 「這張卡片現在宣告的是哪些帳號」要把同一個匿名編號的所有事件依序串起來才知道，所以現況沒有辦法直接附證明。存事件，每一筆才都是可以重驗的。
- **規則公開，營運者就沒有裁量的空間。** 一張卡片在每個平台一個名額、更換的次數上限（ADR-0018）、收回，都寫成規格和參考實作，照著算就有答案。
- **規則可以調整，事件不用動。** 例如更換的次數上限之後要放寬（ADR-0018），改的是規則，已經寫入的事件不受影響。上線之後改規則，已經寫入的紀錄結果也不能變：新舊兩版逐筆比對，有一筆不同就從生效日起才用新規則（ADR-0031）。

## Considered Options

- **存現況（一張「帳號對應卡片」的表），另外留紀錄**：查詢簡單，但表裡的內容是營運者算好的結果，外人只能相信。
- **事件種類分細**（第一次宣告、再次過卡、更換、收回各一種）：它們在證明上是同一件事，差別只在這一份帳號清單和上一份哪裡不同，由規則分辨就夠。收回原本是另一種事件，改成整份清單之後（ADR-0017）也是這樣：收回一個帳號，就是一份少了它的清單。

## Consequences

- 證明紀錄不設到期日。它只記事實和日期，多新的宣告才算數由查詢方和顯示的一方決定；API 的回應一定帶日期，不提供單純的「是或否」。
- 證明紀錄不記卡片序號，所以營運者沒有辦法主動檢查某張卡片的憑證是否已被廢止。這不是還沒做，是做不得：廢止清冊列的是憑證序號，任何能從序號對到匿名編號的方法，發證單位也能拿來查出每個人的匿名編號。廢止只在持卡人過卡的時候檢查，因此上次過卡日是判斷新舊的核心依據。
- 公開的日期只精確到日。
- 證明紀錄裡每一筆事件都附證明，不提供刪除。持卡人能做的是收回。拿掉帳號和匿名編號的對應也刪不掉：宣告碼和題目都公開，把帳號清單代進去算就找得回來。沒有證明的刪除事件，則任何人冒充持卡人都能讓一筆紀錄消失。帳號主人也不能要求隱去自己的帳號名稱：宣告是持卡人單方面的表示，島民證明的頁面會寫明這一點，並讓訪客看得到帳號主人有沒有連回；而同一張卡片在幾個帳號之間輪替的痕跡，正是外人辨認收買名額的線索，能隱去就能被拿來擦掉這些痕跡。
- 證明紀錄怎麼讓外人發現營運者拿掉紀錄、調換順序或給不同的人不同的證明紀錄，見 ADR-0021。這一段原本寫的是每一筆紀錄帶著前一筆的雜湊、串成一條鏈，已由 ADR-0021 取代。
