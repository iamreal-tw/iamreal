# 設計原則

做任何畫面、寫任何介面文字之前先讀這一份。用詞以根目錄的 `GLOSSARY.md` 為準。

iamreal 的賣點是不需要相信營運者。畫面的工作是把事實交給看的人，讓他自己判斷，所以這裡的原則多半是在說「不要做什麼」。

## 四條原則

### 1. 要他知道的，和讓他查得到的，分開

一件事要直接放在持卡人的畫面上，必須同時符合兩個條件：

- 知道了可能會改變他要不要繼續
- 按下去之後很難反悔

其餘收進「了解更多」，一點就看得到，但不擋在路上。

| | 例子 |
|---|---|
| 放在畫面上 | 名額給哪個帳號；會公開什麼；什麼留在這台電腦 |
| 收進了解更多 | 零知識證明怎麼運作；卡片簽幾次；更換的完整規則 |

### 2. 第一屏放最容易誤會的事

訪客不按任何東西，他的風險是帶著錯的印象離開。放在第一屏的，是訪客最可能誤會、而且誤會了會做錯判斷的事。

### 3. 不說得比實際多

畫面帶來的信任不能超過機制真正的強度。寧可少一點安心感，也不要錯誤的安心感。

| 不對 | 對 |
|---|---|
| 鎖頭、盾牌圖示 | 不放圖示，寫出事實 |
| 「絕對安全」「完全匿名」 | 「PIN 留在這台電腦」，並且讓人能自己檢查送出了什麼 |
| 「已驗證」「真人認證」「這個帳號是真人」 | 「有自然人憑證持卡人宣告了 Threads 的 @alice」 |
| 「真人證明名額」 | 「這張卡片在 Threads 唯一的名額」 |
| 略過做不到的事 | 照實寫：拿到卡片和 PIN 的人，查得出這張卡片宣告了哪個帳號 |

### 4. 不下結論

頁面給事實和日期，判斷留給看的人。

- 不用打勾、綠色、「有效」「通過」這類表示結論的元素
- 上次過卡是 12 天前還是 400 天前，樣式相同，差別只在數字；旁邊附固定的過卡頻率建議
- 徽章的圖樣不能像平台的官方認證

理由：一旦畫面替訪客下了結論，被收買的名額也會得到同一個綠色的勾。

## 輸入 PIN 之前的畫面

整個產品裡要求最多信任的一刻。畫面講四件事，不多不少：

1. 名額給哪個帳號
2. 會公開什麼
3. 什麼留在這台電腦
4. 拿到卡片和 PIN 的人查得出這個帳號

```
請插入自然人憑證。
你正在把這張卡片在 Threads 唯一的名額宣告給
@alice
一年最多可以更換帳號兩次。

會公開                        留在這台電腦
· 有一張卡片宣告了 @alice      · PIN
· 一個查不出是誰的編號         · 姓名和憑證
· 今天的日期                   · 卡片的簽章

卡片請自行保管、請勿出借給他人。拿到你的卡片和 PIN 的人，查得出這張卡片宣告了 @alice。  了解更多
```

- 「會公開」和「留在這台電腦」並排成兩欄
- 「還剩幾次更換」要先有匿名編號才算得出來，而匿名編號要卡片簽章後才有，所以不在這個畫面。卡片簽完場合字串後查名冊；這張卡片目前宣告的是別的帳號時，停下來告訴持卡人會用掉一次更換、還剩幾次，確認後才繼續：

```
這張卡片目前宣告的是 @bob。
改成 @alice 會用掉一次更換，之後今年還剩 1 次。

[ 取消 ]    [ 改成 @alice ]
```

## 徽章頁

### 第一屏的三塊

| 訪客的誤會 | 實際上 | 第一屏用什麼擋 |
|---|---|---|
| 這個帳號是真人、是本人 | 只知道有一張卡片把名額用在它身上 | 標題是一句事實：「有自然人憑證持卡人宣告了 Threads 的 @alice」 |
| 這筆宣告現在還算數 | 名冊只有日期，不知道憑證現在是否有效 | 「上次過卡：12 天前」，和標題一樣顯眼 |
| 帳號主人承認這筆宣告 | 任何持卡人都能宣告任何帳號 | 嵌入帳號的個人檔案，加一句「看看這個個人檔案有沒有連回這一頁」 |

歷程摘要、過卡頻率的建議、匿名編號都在下面。每一筆宣告的最後一行固定是重驗的入口：「不用相信這一頁，你可以自己重驗。」

### 兩種頁面

**指定一張卡片的頁面**（`iamreal.tw/threads/@alice/7K2Q9F`）：上面三塊講這一張，往下是這張卡片的歷程。

**帳號頁**（`iamreal.tw/threads/@alice`）：

- 只有一張卡片宣告時，和指定一張卡片的頁面完全一樣
- 有多張時：
  - 標題是同一句話，下接「共 3 張卡片」當清單的小標。張數不放大，旁邊固定說明：「任何持卡人都可以宣告任何帳號，筆數不代表支持或連署。」
  - 每張卡片一列：短編號、開始宣告的日期、上次過卡。點進去是那張卡片的頁面，歷程在那裡看
  - 不合併日期。沒有整個帳號的「最近一次過卡」，否則任何人拿一張卡片宣告這個帳號，就能讓它的頁面看起來很新
  - 個人檔案旁多一句：個人檔案上的連結結尾帶編號（例如 `/7K2Q9F`）時，帳號主人只認那一張。頁面不替訪客標出是哪一張

## 文字的寫法

- 稱呼用「你」
- 帳號一律寫成 `@名稱`
- 第一層的畫面只用這幾個詞：宣告、過卡、徽章頁、名冊、名額。零知識證明、匿名編號這類詞只出現在「了解更多」和完整的說明裡；需要提到匿名編號時寫「一個查不出是誰的編號」
- 每個畫面只做一件事

## 三層

| 層 | 內容 | 放哪裡 |
|---|---|---|
| 原則 | 這一份和 `GLOSSARY.md` | `docs/design/` |
| 文字 | 畫面上每一句給人看的話，各平台共用一份 | `design/copy/` |
| 視覺 | 顏色、字級、間距、元件 | `design/tokens.json` |

視覺那一層還沒有定。順序是先用定好的文字做出輸入 PIN 之前的畫面和徽章頁的樣稿，選定方向後再抽出規則。
