# 設計原則

做任何畫面、寫任何介面文字之前先讀這一份。用詞以根目錄的 `GLOSSARY.md` 為準。

iamreal 的賣點是不需要相信營運者。畫面的工作是把事實交給看的人，讓他自己判斷，所以這裡的原則多半是在說「不要做什麼」。

## 底線和預設做法

這份文件裡的規定分成兩種。

**底線**只有下面五條，畫面怎麼改都不能破；要破，先改這一份：

1. 不說得比實際多（原則 3）
2. 不下結論（原則 4）
3. 畫面和流程都不收身分證字號
4. 做不到的事、收不回的事，在持卡人按下那一下之前，畫面上至少看得到一次，用他第一次看就懂的話
5. 說會公開什麼，要和證明紀錄實際公開的內容一致

**預設做法**是其餘的全部：原則 1 的擺放方式、表格裡的例句、各個畫面「講哪幾件事」。照著做；畫面需要不一樣時可以不照做，在 `design/copy/` 那一句旁邊寫一句理由，不用改這一份。

改字時覺得和這一份衝突，先問一句：這次改動有沒有讓某個事實從整個流程裡消失，或讓畫面說得比實際多？有，就是碰到底線；沒有，只是換位置、換說法、少說一次，就照預設做法的規則處理。

## 四條原則

### 1. 要他知道的，和讓他查得到的，分開

一件事要直接放在持卡人的畫面上，必須同時符合兩個條件：

- 知道了可能會改變他要不要繼續
- 按下去之後很難反悔

放在畫面上的事，在做決定的那一刻說一次，用最少的字，不在好幾步重複。每多一句都在搶讀者的注意力：說得越多，最要緊的那一句越容易被跳過。

其餘不放在過卡的畫面上，寫在常見問題。過卡的畫面預設不連出去：點出去會打斷流程，在 app 裡還會離開 app。例外時寫明理由，例如還沒有卡片的人要知道去哪裡辦。

| | 例子 |
|---|---|
| 放在畫面上 | 這次會記下的整份帳號清單，每一列會發生什麼；會公開什麼，哪些帳號會列在一起；什麼留在這台裝置 |
| 寫在常見問題 | 零知識證明怎麼運作；卡片簽幾次；更換的完整規則 |

### 2. 第一屏放最容易誤會的事

訪客不按任何東西，他的風險是帶著錯的印象離開。放在第一屏的，是訪客最可能誤會、而且誤會了會做錯判斷的事。

### 3. 不說得比實際多

畫面帶來的信任不能超過機制真正的強度。寧可少一點安心感，也不要錯誤的安心感。

| 不對 | 對 |
|---|---|
| 鎖頭、盾牌圖示 | 不放圖示，寫出事實 |
| 「絕對安全」「完全匿名」 | 「PIN 不會離開這台裝置」，並且讓人能自己檢查送出了什麼 |
| 「已驗證」「真人認證」「這個帳號是真人」 | 「有自然人憑證持卡人宣告了 Threads 的 @alice」 |
| 「真人證明名額」 | 「這張卡片在 Threads 唯一的名額」 |
| 略過做不到的事 | 照實寫，在做決定之前至少說一次。例如：拿到卡片和 PIN 的人，查得出這張卡片宣告過的帳號 |
| 「@alice 是真人，他在別的平台的同名帳號也是」 | 證明只涵蓋島民證明上列出的帳號 |

### 4. 不下結論

頁面給事實和日期，判斷留給看的人。

- 不用綠色、「有效」「通過」這類表示結論的元素
- 打勾只用在過卡流程的進度清單，表示「這一步做完了」，用墨色。島民證明的頁面和過卡完成的畫面不放打勾：前者是訪客判斷帳號的地方，後者會被截圖貼出去
- 上次過卡是 12 天前還是 400 天前，樣式相同，差別只在數字；旁邊附固定的過卡頻率建議（每三個月一次）
- 島民證明和記號的樣子不能像平台的官方認證

理由：一旦畫面替訪客下了結論，被收買的名額也會得到同一個綠色的勾。

## 首頁和事實頁

上面四條原則是寫給**事實頁**的：首頁以外的每一頁和每一個畫面。島民證明頁、查詢頁、證明紀錄頁、常見問題、如何檢查 Threads 帳號的島民證明、如何驗證證明紀錄、掛上去、過卡需要什麼、隱私權說明，網頁和 app 過卡的每一個畫面（完成後邀請分享的那一段除外，見下面），app 的提醒和設定，都是事實頁。訪客在這些頁面判斷別人的帳號，持卡人在這些頁面做很難反悔的事，所以一字不放寬。

**首頁**、連結預覽圖，和過卡完成後邀請分享的那一段，是說明和號召的地方，工作是讓人看懂、願意參與。持卡人在那一段已經做完決定，要做的只剩要不要分享，所以可以用情感打動他。它們可以：

- 用比較強的語氣，說整體的效果，例如「大幅增加輿論操作的成本」
- 寫「台灣人」：「讓人知道你是真的台灣人」「宣告你的 Threads 帳號是台灣人持有」
- 說明機制時，寫「宣稱自己是某個帳號的持有者」。讀的人多半是要替自己帳號換證明的人，「宣稱」也講明了這只是主張
- 用「真人」描述問題和整體的情況，例如「假扮真人的帳號」「留言區的真人程度」

首頁的四條底線，和事實頁一樣不能碰：

1. 不說**某一個**帳號是真人、是本人、「已驗證」，也不說帳號能被驗證
2. 隱私和安全的保證照實寫，不寫絕對。寫得出根據的才寫：「不會透露你的姓名、身分證字號，也看不出是哪一張卡片」，不寫「不會暴露任何個資」「完全匿名」「絕對安全」
3. 還沒做的功能標「之後」「未來」或「願景」
4. 不說島民證明的數字或比例代表民意

首頁上的常見問題，答案和常見問題頁同一題逐字相同，照事實頁寫。

| 首頁可以 | 事實頁要寫成 |
|---|---|
| 「宣告你的 Threads 帳號是台灣人持有」 | 「一張台灣國民的自然人憑證宣告了 Threads 的 @alice」 |
| 「有一張台灣自然人憑證替這個帳號背書」 | 同左，但不放在帳號名稱旁邊當記號 |
| 「這會大幅增加假扮真人帳號的成本」 | 不寫 |

## 輸入 PIN 之前的畫面

整個產品裡要求最多信任的一刻。這時候還不知道持卡人要做什麼：這張卡片宣告過哪些帳號，要卡片簽了場合字串才查得到。所以流程是先確認卡片，再看這張卡片的帳號清單、在清單上改，最後才是宣告。

輸入 PIN 的畫面，預設在 PIN 欄位旁邊講三件事：

1. PIN 用來做什麼：卡片會簽章一次，用來查這張卡片目前宣告的帳號；這一步還不會宣告，確認之前不會公開任何東西
2. 什麼不會離開這台裝置：PIN、姓名和憑證、卡片的簽章
3. 拿到卡片和 PIN 的人，查得出這張卡片宣告過的帳號

前兩件和 PIN 欄位在同一個畫面，不放在前一步：讀的人要在輸入的當下看得到。第三件是要不要宣告的考量，也可以只放在確認的畫面，但兩個畫面至少一個要有（底線 4）。

「會記下哪些帳號」和「會公開什麼」放在卡片第二次簽章之前的畫面。那才是很難反悔的一下，那時也才知道整份清單。

- 一步一個畫面，上方寫「第 2 步，共 7 步」：開始之前、讀取卡片、輸入 PIN、你的帳號、確認、掛上去、完成和分享。app 在掛上去和完成之間多一步過卡提醒，共 8 步。沒有選平台的畫面：一次過卡處理這張卡片的整份帳號清單
- 讀取卡片和最後的進行中，逐項列出頁面正在做的事，每一項有自己的狀態（進行中、完成、停在這裡）。停下來時，原因寫在停住的那一項下面，回報問題的人說得出停在哪裡
- 流程是三次點擊：讀取卡片、確認卡片（卡片簽場合字串）、最後的確認（卡片簽宣告碼）。「讀取卡片」不用 PIN，讀到憑證後才出現 PIN 欄位；過不了的卡在這裡就告訴持卡人原因，不要求 PIN
- 讀到憑證後，在 PIN 欄位上方顯示卡片上的姓名，並註明只顯示在這裡、不會送出。在別人的卡片上輸入自己的 PIN 會用掉那張卡片的錯誤次數，這是輸入 PIN 之前唯一能擋下插錯卡的地方；姓名只出現在這一步
- 卡片簽完場合字串後，第 4 步照這張卡片的情況分流。沒有任何宣告（沒宣告過，或全部收回過）時，只有填帳號的欄位，填上的是新宣告。已經有宣告時，寫出目前宣告的帳號和上次過卡幾天前，主按鈕「更新島民證明」就是再次過卡，次要的動作是「改成別的帳號」和「收回對 @alice 的宣告」；選了「改成別的帳號」才講更換的上限。平台表有不只一個平台時，次要的動作合成「修改帳號清單」，展開後每個平台一列，各自改：填上空白的是新宣告，改成別的帳號是更換，清空是收回。最常做的再次過卡不用重打帳號，也就不會因為打錯字用掉一次更換
- 不引導把每個平台都填滿：沒有「還有平台沒填」這類提示。不要讓人為了填滿，宣告一個不想被認出來的帳號
- 平台的列來自後台給的平台表，但只有裝置自己認得的平台可以改；後台列了、裝置不認得的平台，這張卡片在那裡有帳號時顯示成不能修改的一列，原樣保留（ADR-0019）
- 改完之後**一律**停在確認的畫面，確認後卡片才簽第二次。這個畫面列出要簽的整份清單，每一列寫會發生什麼（不變、新宣告、更換、收回），會被收回的帳號也列出來；寫出紀錄無法刪除和它的理由、用掉幾次更換。很難反悔的那一下永遠是最後一下
- 宣告的帳號會公開列在同一張島民證明上。這件事知道了可能改變要不要繼續，公開之後收不回來，所以放在第一步和確認的畫面上，和其他內容一樣顯眼，不收進可以展開的問題。裝置上只有一個平台可以填時，沒有別的帳號可以列，這一段不顯示
- 講會公開什麼的句子，要和證明紀錄裡實際公開的內容一致：寫「宣告了 @alice」，不寫「宣告自己是 @alice」；寫「有效的」，不寫「合法的」
- 更換一個平台終身最多 5 次，用掉就不會恢復（ADR-0018）：寫「還可以更換 2 次」「終身最多只能更換 5 次」「用掉一次更換，不會恢復」這類讓人知道次數不會重新計算的寫法，不寫「今年」「一年內」。每一列寫這個平台還可以更換幾次；完整的規則寫在常見問題
- 當天才宣告或才更換的帳號，當天改掉是更正，不算更換。畫面在那一列說明今天改掉不另外算一次；確認之後日期換了一天，結果會和畫面說的不同時，卡片不簽，請持卡人從頭來

完整的文字在 `design/copy/card-proof.md`。

## 島民證明的頁面

這一頁的文字在 `design/copy/proof-page.md`，版面在 `design/DESIGN.md` 和 `design/screens/`。標「待定」的等設計時再定，做畫面的人不要自己補。

### 已經定的

- 一張卡片一頁，網址是 `iamreal.tw/p/7K2Q9FM4XD`（ADR-0020）。頁面列出這張卡片現在宣告的帳號和上次過卡日。第一次上線只有 Threads
- 頁面說「這張卡片宣告的帳號」，不說「同一個人的帳號」（ADR-0017）
- 頁面不標「已確認」「帳號主人承認」這類的話。系統不確認帳號主人承不承認（ADR-0003）；頁面做的是讓訪客自己看得到
- 上次過卡是幾天前，和標題一樣顯眼；下面接這張卡片的整份證明紀錄，全部列出、不折起來；紀錄下面附固定的過卡頻率建議（每三個月一次）
- 第一屏最大的字是帳號名稱。訪客第一件事是比對這一頁列的是不是他來的那個帳號
- 標題的主詞是自然人憑證，不是人：「一張台灣國民的自然人憑證宣告了 Threads 的 @alice」。證明確認的是一張國民的正卡簽了章，簽的人不一定是自然人憑證上的那個人
- 嵌入框上方印出要比對的連結，寫法和 Threads 顯示的相同。頁面讀不到嵌入框裡的內容，所以不放依情況切換的句子。嵌入框下面不放句子，連到 Threads 個人檔案的連結放在嵌入框上方那一句裡
- 頁面不偵測帳號有沒有改名。證明紀錄裡是哪個名稱，頁面就寫哪個名稱
- 頁面裡不放「如何檢查」的段落：頁首的選單和頁尾都連到「如何檢查 Threads 帳號的島民證明」（`/check`）。頁面不顯示「驗證通過」，頁面的內容不連到「如何驗證證明紀錄」：想自己重算的人從「如何檢查」那一頁的最後一條過去
- 字越少越好。訪客在這一頁只看三件事：帳號是誰、帳號主人的個人檔案上有沒有這張證明的連結、上次過卡是哪一天；其他的說明放在「如何檢查」那一頁

### 要擋的誤會

| 訪客的誤會 | 實際上 | 用什麼擋 |
|---|---|---|
| 這個帳號是真人、是本人 | 只知道有一位持卡人把一張卡片在這個平台的名額給了它 | 標題是一句事實：「一張台灣國民的自然人憑證宣告了 Threads 的」，下一行是最大的 @alice |
| 這筆宣告現在還算數 | 證明紀錄只有日期，不知道憑證現在是否有效 | 「上次過卡：12 天前（2026-11-06）」，和標題一樣顯眼，下面接整份證明紀錄。桌機在第一屏的右欄；手機排在個人檔案後面。那一天檢查了什麼，寫在「如何檢查」第 4 步 |
| 帳號主人承認這筆宣告 | 任何持卡人都能宣告任何帳號，系統不確認 | 嵌入 Threads 的個人檔案；上方一句寫出判斷的條件（「個人檔案上有這個連結，才代表 @alice 承認本證明。」）和要比對的連結。頁面不回答這一題 |
| 證明也涵蓋這個人在別處的帳號 | 證明只涵蓋這一頁列出的帳號 | 標題寫出平台（「宣告了 Threads 的」）；名稱要一字不差、其他平台上同名的帳號不算，寫在「如何檢查」那一頁 |

### 查詢頁

`iamreal.tw/threads/@alice` 是查詢頁：列出有哪些卡片宣告了這個帳號，每一張連到它的島民證明。已經定的兩件事：

- 張數不放大，旁邊固定說明：「任何持卡人都可以宣告任何帳號，張數不代表支持或連署。」
- 不合併日期。沒有整個帳號的「最近一次過卡」，否則任何人拿一張卡片宣告這個帳號，就能讓它看起來很新。頁面不替訪客標出帳號主人認的是哪一張
- 排法和文字已經定了，在 `design/copy/account-page.md`；證明紀錄頁在 `design/copy/proof-log-page.md`

### 待定

- 之後加的平台不能嵌入時怎麼讓訪客看到；一張島民證明列著好幾個帳號時的版面
- 之後有第二個平台時，查詢頁和證明紀錄頁的排法

## 文字的寫法

- 稱呼用「你」
- 帳號照它所在平台的寫法寫（Threads 是 `@名稱`）；寫法寫在裝置上
- 第一層的畫面只用這幾個詞：宣告、過卡、島民證明、島民編號、證明紀錄、更換、收回、零知識證明。匿名編號、場合、宣告碼這類只在協定裡的詞不出現在畫面上；匿名編號在畫面上叫「島民編號」，只顯示開頭的 10 個字元（短編號對到兩張以上時，寫到分得開為止）
- 畫面上的詞要讓第一次看的人就懂。我們內部的稱呼換成讀者的說法：「營運者」寫「我們」，「平台」寫它的名字（Threads）
- 每個畫面只做一件事
