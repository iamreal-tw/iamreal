# web/：網頁版的過卡

**這個目錄讓人檢查的事：憑證、公鑰、簽章、PIN 沒有離開持卡人的裝置。** 這裡是從「讀到卡片上的憑證」到「送出證明」之間，在持卡人的瀏覽器裡做的每一件事：過卡的引擎（`src/`，不含畫面）、內政部元件的橋接（`src/card/hipki.ts`）、過卡的畫面（`src/ui/`）。

程式照 `spec/` 和 `docs/api/card-proof.md` 實作，不引用 `server/`。裝置上的保護照 ADR-0015、ADR-0016：保護持卡人、對抗伺服器的限制寫死在這裡，伺服器只能讓它更嚴。

## 在本機用真卡片過卡

需要 Node 22（22.6 以上）、pnpm 10、Go 1.26、`bb` 6.0.0（取得方式見 `verifier/README.md`）、讀卡機和內政部的元件（HiPKI，`http://localhost:61161`）。

```
cd web
pnpm install --frozen-lockfile
IAMREAL_BB=/path/to/bb pnpm local          # 可加 --port 8080、--data <目錄>
```

`pnpm local`（`scripts/local.ts`）依序：通用參數不在就下載（`pnpm fetch-crs`）、建置正式的頁面（`vite build --mode production`：內政部的發證金鑰、元件在 `http://localhost:61161`）、建置後台（不帶測試的建置標籤）、跑一次清冊鏡像（抓內政部真的 G2、G3 清冊）、用測試的名冊啟動後台並提供頁面，在 `http://localhost:8080/`。按 Ctrl-C 停止。名冊、清冊、後台的執行檔在 `web/local/`（不進版控）；刪掉這個目錄就從空的名冊重來。

用桌機的 Chrome 開 `http://localhost:8080/`。`localhost` 是瀏覽器認定的安全來源，不需要 HTTPS：在後台送的標頭之下，頁面是跨來源隔離的（多執行緒），也能和元件的視窗來回（2026-11-16 在這台 Mac 的 Chrome 157 實測，只送 `CheckEnvir`：`test/e2e/check-component.ts`）。Safari、Firefox 忽略 `Document-Isolation-Policy`，證明用 1 個執行緒；這一頁沒有在它們上面測過。後台另外送 `Cross-Origin-Opener-Policy: same-origin-allow-popups`（見「頁面需要的標頭」）；加了它之後元件還能不能用，Chrome 以外的瀏覽器和真的過卡還沒有確認。

確認頁面本身沒問題、但還不想插卡時：`node --experimental-strip-types test/e2e/smoke.ts http://localhost:8080/` 用無頭 Chrome 開到第一個畫面為止（不按「讀取卡片」，元件不會收到任何請求），檢查標頭、跨來源隔離、證明引擎啟動、沒有違反 CSP、沒有連到別的網域。

## 畫面和引擎怎麼分層

| 層 | 檔案 | 做什麼 | 不做什麼 |
|---|---|---|---|
| 畫面 | `src/ui/` | `design/copy/card-proof.md` 的選平台和六步、三次點擊；兩張清單每一項的狀態、停住時的原因寫在哪一項下面；把停止原因、這張卡片的現況和選了之後的後果對到 `design/copy/card-proof.json` 的句子（`messages.ts`）；在點擊裡開元件的視窗，被擋時不往下做 | 不檢查任何東西、不碰憑證和簽章的位元組；沒有自己的句子（`test/copy.test.ts` 檢查 `src/ui/` 和 HTML 裡沒有中日韓文字） |
| 平台的定義 | `src/platforms.ts` | 每個平台不同的東西（見下面「每個平台不同的東西」） | 沒有句子；格式的提示是 `card-proof.json` 的鍵 |
| 引擎 | `src/flow.ts`、`src/index.ts` 和其他 | 全部的檢查、何時讓卡片簽、何時查現況、每個選項是哪一種、拒絕不能做的選項、PIN 留多久、算證明、送出；做完一件事就告訴畫面（`onProgress`） | 不知道有畫面 |
| 卡片 | `src/card/card.ts` 的介面；`hipki.ts`（元件）、`fake.ts`（測試金鑰） | 讀憑證（不用 PIN，元件有回應時先說一聲）、簽 31 個位元組（要 PIN），簽章附上實際簽章的憑證 | 不判斷憑證能不能用 |

畫面的文字在 `design/copy/card-proof.json`，是 `design/copy/card-proof.md` 的句子照畫面分組、例子換成 `{名稱}`（`{account}` 是帶前綴的帳號，例如 `@alice`）。`test/copy.test.ts` 兩個方向都比：JSON 的每一句代入 Markdown 的例子後，在 Markdown 裡一字不差；Markdown 的每個畫面（程式碼區塊）和表格裡「畫面寫」「標題」「名冊會公開記下」「按鈕」那幾欄的每一格，都由 JSON 的句子組成，剩下的只能是照原樣顯示的值（例子的帳號、日期、姓名、完成畫面的連結，`src/platforms.ts` 的平台名稱和前綴）和 Markdown 畫按鈕、清單、可展開問題的符號（`[ ]`、`›`、`▸`、`○`、`·`）。「（QR code）」和「第 2 步那張表裡同一種情況的句子」是文件的註，不比。文件裡沒有的句子，畫面只顯示代碼（見「停止的原因」）。唯一不在那份 Markdown 裡的是說明頁的「待補」。

`card-proof.json` 的 `app` 那一組（選裝置、用手機過卡）是 app 推出之後用的：畫面現在不顯示它們（`card-proof.md`「app 推出之前」），文字測試照樣比對它們在 Markdown 裡。

說明頁（「怎麼準備」「了解更多」「怎麼驗證」，和完成畫面的「打開這張島民證明」）是 `help.html?topic=…`，只有標題和「待補」，在新分頁開：離開這一頁，過卡就中斷了。島民證明的頁面還沒做，「打開這張島民證明」先指到說明頁。

每個畫面的頁首是記號和服務的名稱「島民」（`card-proof.json` 的 `common.service_name`）。

**字體**：頁面不載入任何字體檔。後台送的 CSP 是 `default-src 'none'` 而沒有 `font-src`，字體檔即使放在自己的網域也會被擋；要用視覺設計定的字體（源泉圓體、思源黑體、芫荽），得先在 CSP 加 `font-src 'self'`（放寬 CSP，還沒有決定）。`style.css` 的字體依序寫這幾個字體的名稱，電腦裝了就用，沒裝就用系統的字體。

## 每個平台不同的東西

`src/platforms.ts` 是唯一一份：名稱（`Threads`）、帳號前面的字（`@`）、帳號名稱的格式（`validUsername`）和格式不對時的提示（`card-proof.json` 的 `formats` 裡的鍵）、輸入的整理（去掉一個前綴、ASCII 大寫改小寫）、帳號公開頁面的網址（`profileUrl`，沒有的平台寫 `null`，畫面就不顯示「預覽個人檔案」）、島民網站上這個帳號的路徑（`threads/@alice`）、兩個名冊的場合字串、是不是開放。Threads 開放；X 列在選平台的畫面上、標「還沒開放」、不能選，沒有場合字串。畫面和引擎其他地方沒有寫死的平台名稱、`@`、場合字串：`src/spec/scope.ts` 的場合字串表由這份定義產生，**場合字串仍然只從這份寫死的定義來**，不從伺服器或網址來。島民網站的網域（`iamreal.tw`）是同一個檔案的 `SITE_DOMAIN`，只用在完成畫面寫的連結；頁面不連到它。

## 兩張清單和引擎的對應

讀取卡片（第 2 步）和進行中（第 5 步）逐項列出頁面正在做的事。引擎每做完一件事呼叫 `onProgress`（`src/flow.ts` 的 `Progress`），畫面把它對到清單的項目（`src/ui/messages.ts` 的 `READ_ITEMS`、`PROGRESS_ITEMS`）。事件只是回報，不改引擎檢查什麼、檢查的順序；流程停下之後不再有事件。

| 清單的項目 | 哪些事件都到了才算完成 | 引擎實際做的事 | 停在這裡的原因（`Stop`） |
|---|---|---|---|
| 連上內政部的元件 | `component` | 元件的視窗說準備好了（`hipki.ts`） | `card` `component_unreachable` |
| 找到讀卡機和卡片 | `certificates` | `GetUserCert` 回了憑證 | `card` `no_reader`、`no_card` |
| 讀取卡片上的憑證 | `certificates` | 同上 | `certificate` `no_certificate`；`card` `card_error`、`card_locked` |
| 檢查憑證 | `certificate` | `selectCertificate`：照電路的走法預先檢查、選出那一張 | `certificate` 的其他原因（含 `ambiguous_certificate`：兩張都通過） |
| 連上島民的伺服器 | `config`、`circuit`、`engine` | `GET /api/v1/config`；電路檔的 SHA-256；證明引擎啟動（含通用參數的 SHA-256） | `server`（讀設定時）、`artifact`、`engine` |
| 下載內政部的廢止清冊，確認憑證沒有被廢止 | `crl`、`tree` | 清冊下載並驗過；建樹，序號不在樹裡 | `revocation`、`revoked` |
| （進行中）連上島民的伺服器 | `challenge` | 要題目、檢查題目；憑證和清冊用當下的日期再檢查 | `challenge_not_today`、`challenge_malformed`、`server`（要題目時）、`certificate` `expired`、`revocation` `crl_stale` |
| 卡片簽章 | `signed` | 卡片簽宣告碼，用憑證驗過 | `card`、`card_signature` |
| 在這台裝置上計算，大約 10 到 30 秒 | `proved` | 算證明，公開輸入和裝置重建的相同 | `engine`、`proof_check` |
| 送出 | （完成的畫面） | `POST /api/v1/records` | `server` 的送出錯誤 |

讀卡之後，設定、電路檔、證明引擎、清冊、建樹同時進行，事件的先後不定；清單照上表的順序顯示：一項的事件都到了，而且它上面每一項都完成，才顯示「完成」；第一個還沒完成的那項顯示「進行中……」。停下來時：讀取卡片照上表把原因寫在對應的那一項下面（表上沒有的原因寫在第一個還沒完成的項目下）；進行中是依序做的，寫在第一個還沒完成的項目下面。停住的那項上面還沒完成的項目（例如清冊先出錯時，伺服器那一項還沒完成）不顯示狀態，下面的也不顯示。完成的項目前面是墨色的勾（`style.css` 畫的，不是圖示）；完成的畫面沒有勾。

## 預覽個人檔案

第 4 步輸入帳號的地方有「預覽個人檔案」：帳號格式對的時候，用 `window.open(平台的帳號網址, "_blank", "noopener,noreferrer")` 在新分頁開平台上這個帳號的頁面（Threads 是 `https://www.threads.com/@帳號`）；格式不對時不開，顯示格式的提示。**這是這一頁唯一會帶人到別的網域的地方**：新分頁只拿到網址裡的帳號名稱，不帶任何過卡的資料（沒有開啟者：`noopener`；沒有 `Referer`：`noreferrer`；網址只有平台的帳號網址加上輸入的帳號）。過卡的頁面不嵌入、不 `fetch`、不載入平台的任何東西。CSP 不管 `window.open`，`Cross-Origin-Opener-Policy: same-origin-allow-popups` 允許頁面開新視窗，所以不用改任何標頭；`test/e2e/ui.ts` 在這兩個標頭之下點了預覽：頁面呼叫的正是 `window.open(平台的帳號網址, "_blank", "noopener,noreferrer")`、瀏覽器開出一個新分頁而且新分頁拿不到這一頁（`canAccessOpener` 是 `false`）、這一頁自己沒有對別處發請求、沒有違反 CSP；頁面呼叫的 `window.open` 只有元件的視窗和這一個。新分頁在無頭測試裡沒有開始載入（測試用 DevTools 把每個新分頁停住，`noopener` 的分頁即使是本機的網址也沒有放行，試過），所以「平台的頁面在新分頁裡打開」沒有在自動測試裡看到，要用有畫面的瀏覽器自己點一次看；測試的瀏覽器也不解析 localhost 以外的名稱，不會連出去。

## 流程

先確認卡片，再選要做的事，最後才宣告（`docs/design/principles.md`「輸入 PIN 之前的畫面」）。三次點擊，每次開一次元件的視窗。

| `card-proof.md` | 畫面 | 點擊 | 引擎（`src/flow.ts`） |
|---|---|---|---|
| 選平台 | 開放的平台（Threads）可以按；還沒開放的（X）列出、標「還沒開放」 | | 選的平台決定場合字串（`src/platforms.ts`） |
| 1. 開始之前 | 準備實體卡片、只收國民正卡、兩個可以展開的問題；「上一步」回到選平台、「下一步」到讀取卡片（app 推出之前沒有選裝置的按鈕）。5 分鐘到時回到這裡，最上面是那一句 | | |
| 2. 讀取卡片 | 六項的清單（見「兩張清單和引擎的對應」）；全部完成後「讀取卡片」換成「下一步」；停住時原因寫在那一項下面，「讀取卡片」換成「再讀一次卡片」（新的一次過卡）。不顯示姓名 | 讀取卡片（開視窗） | `readCard()`：讀憑證、預先檢查；開始不需要簽章的檢查（設定、清冊、建樹、電路檔、通用參數）；`checksDone()` |
| 3. 輸入 PIN | 「已讀到卡片」、姓名、「（姓名只顯示在這裡，不會送出。）」；PIN 欄位，下面是三件事；按下後「卡片簽章中，接著查……」，到這一步結束（換到第 4 步，或停下、可以再試）之前，PIN 欄位和按鈕都不能用。PIN 錯、視窗被擋可以在同一步再試；其他停住（鎖卡、讀卡錯誤、伺服器）原因寫在 PIN 欄位下面，「確認卡片」不能再按，「上一步」回到讀取卡片 | 確認卡片（開視窗） | `confirmCard(pin)`：卡片簽場合字串、算匿名編號、查現況；從現況和今天的日期算出每個選項是哪一種（`CardStatus.options`）、過去一年更換過幾次、還剩幾次、下一次可以更換的日期、今天是不是已經有 3 筆有效紀錄（`CardStatus.dailyLimit`）。「上一步」：`cancel()`，回到第 2 步，重新讀一次（新的流程物件，PIN 欄位清空） |
| 4. 選要做的事 | 現況的幾行；還沒宣告過：輸入帳號（含「預覽個人檔案」）；宣告過：再次過卡、改成別的帳號、收回；收回過：宣告回同一個帳號、宣告別的帳號。更換用完時「改成別的帳號」「宣告別的帳號」不能按，下面寫下一次可以更換的日期。「新的帳號」的畫面有「上一步」。今天已經過卡 3 次時，現況的幾行照樣顯示，下面是「這張卡片今天在 Threads 已經過卡 3 次，明天才能再過卡。」和「回到開頭」（和「取消」一樣丟掉 PIN）。「取消」回到選平台 | 不碰卡片 | `choose(選擇)`：算出後果（`Consequence`，含這次更換之後下一次可以更換的日期）。帳號格式不對、被上限擋住（更換次數、今天 3 筆）、沒有可收回的，引擎自己拒絕（`FlowStop`，流程不結束） |
| 5. 確認 | 名冊會公開記下的那一句、帳號、日期、島民編號開頭；更換時用掉幾次（用完時寫下一次可以更換的日期）；紀錄不能刪除和它的理由；「上一步」回到選的那個畫面；「取消」 | 宣告給／再次過卡／改成／收回（開視窗） | `back()` 回到現況，不重新簽章、不重新查；`proceed(帳號)`：要題目、檢查、卡片簽宣告碼、丟掉 PIN、算證明、送出 |
| 5. 進行中 | 四項的清單；計算那一項進行中時多一句零知識證明的說明。停住時原因寫在那一項下面，下面是「回到上一步」（PIN 還在時）或「再讀一次卡片」（PIN 已經丟掉時），送不出去時多一個「再試一次」（只重做送出） | | `resubmit()`：送不出去時原封不動再送；再送得到 `challenge_used` 時查一次現況（見下面） |
| 6. 完成 | 記號的動畫（`prefers-reduced-motion` 時不動）、標題、島民證明、連結和「複製連結」、「打開這張島民證明」、名冊記下的那一筆、「回到開頭」。收回時沒有動畫、島民證明、連結那一段和過卡頻率的建議 | | |

第 4、5 步之間可以來回。從第一次簽章完成起 5 分鐘（`IDLE_MS`）內沒有完成第二次簽章，引擎丟掉 PIN、憑證和簽章，流程停下（`idle`），畫面回到第 1 步、顯示「超過 5 分鐘沒有完成，……請再讀一次卡片。」。這在兩次簽章之間的每一步都成立，包括等後台回答現況、等題目的時候：伺服器不回答，也拖不過這 5 分鐘。第 4、5 步的「取消」、第 4 步滿 3 筆時的「回到開頭」、第 6 步的「回到開頭」都回到選平台：`cancel()` 丟掉 PIN、憑證和簽章（流程物件手上的那一份清成 0，見「已知的限制」）、停掉 5 分鐘的計時器，不顯示任何句子。`cancel()`、5 分鐘到了、任何停下之後，還在等待中的那一步（等卡片、等後台、等算證明）等到之後什麼都不寫回流程物件、不再發任何請求：每一步在每個 `await` 之後都先看流程是不是已經停了。一步還在進行中又被呼叫一次（`readCard`、`confirmCard` 在進行中時不離開自己的階段），和在不對的階段呼叫一樣丟出 `state`：不碰卡片、不發請求，進行中的那一次照常走完。5 分鐘的計時器最多一個：開始前先取消舊的。之後再按「讀取卡片」是新的一次過卡，用進頁面時啟動的同一個證明引擎（ADR-0013），不重新整理頁面。

**進行中停住之後的按鈕**（`src/ui/messages.ts` 的 `progressButtons`，看引擎停住後的 `phase`）：PIN 還在引擎裡的時候（`chosen`：第二次簽章的視窗被瀏覽器擋下，什麼都沒送到卡片），按鈕是「回到上一步」，回到第 5 步，同一個按鈕再按一次。其他停住時引擎都已經丟掉 PIN（流程結束；或者第二次簽章已經完成，PIN 在那時就丟了，送不出去、題目過期 `challenge_unknown` 都是這種），按鈕是「再讀一次卡片」：回到第 2 步，在同一次點擊裡重新讀卡（新的一次過卡，要重新輸入 PIN）。送不出去時多一個「再試一次」，只重做送出。按下最後一個按鈕時視窗就被擋，畫面不會到進行中，停在第 5 步、顯示被擋的那一句；橋接在進行中才回報被擋（`popup_blocked`）的情況，從畫面上走不到（點擊時開得出視窗，送請求時就一定有那個視窗）。

**送出逾時、其實後台收下了**：第一次送出沒有回答（逾時、連線中斷），後台可能已經寫入。按「再試一次」原封不動再送，後台回 `challenge_used`（這個題目已經有一筆被接受，題目只有這次過卡有）時，引擎再查一次這張卡片的現況（`POST /api/v1/card-state`，帶的匿名編號就是送出的那筆紀錄裡的）：宣告的話，`current` 是這個帳號而且 `last_card_proof` 是這筆紀錄的日期（題目的日期）；收回的話，`current` 是空的、`last_declared` 是這個帳號、`last_card_proof` 是這筆紀錄的日期，就當成完成，到第 6 步。這時沒有 `seq` 和 `account_cards`，連結用帶島民編號的那一種，也不寫「已經有別的卡片宣告了……」。不相符時停在「這次過卡沒有被接受（代碼 challenge_used）」；這時現況讀不懂或沒有回答，停在那個原因（「伺服器的回應不正確……」），不說名冊沒有變動。只在 `resubmit()` 之後這樣做：第一次送出就得到 `challenge_used` 照舊停下。

**完成畫面的連結**：送出成功的回應有 `account_cards`（套用這筆之後，這個場合裡目前宣告這個帳號的卡片數，`docs/api/card-proof.md`）。是 1 時連結是帳號的頁面（`iamreal.tw/threads/@alice`）；大於 1 時帶這張卡片的島民編號（`iamreal.tw/threads/@alice/7K2Q9F`），上面多一句「已經有別的卡片宣告了 @alice，……」。`account_cards` 沒有、或不是非負整數時，當成不知道：紀錄已經寫進名冊了，不為這個欄位停下；連結帶島民編號、不寫那一句（`seq`、`record_hash`、`kind` 照舊嚴格讀）。「複製連結」把 `https://` 開頭的完整網址寫進剪貼簿（`navigator.clipboard.writeText`），成功後按鈕寫「已複製」。`account_cards` 只用來選連結；它錯了也查不出持卡人是誰。

## PIN 經過哪些程式

1. 第 3 步（輸入 PIN）的欄位（`src/ui/app.ts` 的 `pin`）：`type="password"`、`autocomplete="off"`、沒有 `name`、不在 `<form>` 裡。按「確認卡片」時讀一次欄位的值，**欄位立刻清空**，值只交給 `flow.confirmCard(pin)`。欄位是空的時候按鈕不能按，所以不會送出沒有 PIN 的請求。按下之後到這一步結束，欄位和按鈕都不能用，所以卡片不會因為再輸入、再按一次而多簽一次。
2. 引擎（`src/flow.ts`）：第一次簽章成功後存在記憶體裡（PIN 錯、視窗被擋時不留），到第二次簽章完成、流程停下、持卡人按「取消」、或第一次簽章後 5 分鐘（`IDLE_MS`）為止，交給卡片兩次。5 分鐘由計時器（`setTimeout`）觸發，在兩次簽章之間的每一步都會動作，包括等後台回答現況和題目的時候；分頁在背景、電腦睡眠時瀏覽器可能把計時器延後（延多久沒有量），所以 `choose`、`back`、`proceed` 也各自先看時鐘，`proceed` 在拿到題目之後、讓卡片簽第二次之前再看一次，過了就不用它、直接停下。PIN 交給元件做第二次簽章之後，計時器就不再動作：這時 PIN 已經在送往卡片的請求裡，那一步由橋接自己的上限結束（視窗 8 秒內沒準備好、送出後 30 秒沒有回應），結束時引擎丟掉 PIN。持卡人在第 4、5 步來回、看後果的這段時間，PIN 一直在這裡。
3. 橋接（`src/card/hipki.ts` 的 `sign`）：放進一個請求字串，用 `postMessage` 送到元件的來源（`targetOrigin` 寫死），然後丟掉；這個物件沒有任何欄位存它。PIN 是空的、或含 `+`、`%`、可見的 ASCII 以外的字元時不送（見下面）；後兩種畫面在 PIN 欄位下面顯示「這一頁不支援含有 +、% 或非英數符號的 PIN。……」，流程結束，「上一步」回到讀取卡片。
4. 元件的視窗，再到卡片。

沒有任何儲存空間、網址、紀錄、全域變數、DOM 的屬性存過它：`test/e2e/ui.ts` 在每次用過 PIN 之後，檢查欄位、整份 HTML、網址、`localStorage`、`sessionStorage`、`window` 上的每個值都沒有它。JavaScript 的字串不能清成 0，做得到的是不再持有它的參照。

PIN 錯（元件回 `ret_code` `0x76100006`、`last_error` `0xA0`）時，畫面顯示「PIN 不正確。……」、欄位是空的，持卡人重新輸入、再按一次才會再送；任何不成功的回應都不會自己重送。按「確認卡片」時視窗被擋，PIN 照樣在按下時從欄位清掉、沒有交給引擎：允許視窗之後重新輸入、再按一次。按最後一個按鈕時視窗被擋，PIN 留在引擎裡（本來就在兩次簽章之間），5 分鐘的上限照算。

## 元件的橋接信任什麼

`src/card/hipki.ts`。元件沒有 CORS 標頭，頁面不能用 `fetch` 呼叫它；它提供一頁 `/popupForm`，頁面用 `window.open` 開成視窗，視窗準備好時對開它的頁面送 `{"func":"getTbs"}`，頁面送一個請求，視窗做完把回應送回來、自己關掉。照 PSE 範例（`hipki-popup.ts`、`hipki-client.ts`）和 `web-isolation-bench` 量測頁的做法自己寫，沒有複製。

- **網址寫死**：`http://localhost:61161`（`src/target.ts`），不從伺服器的回應或網址參數來。測試的建置換成假元件的網址；`test/build.test.ts` 檢查正式的建置只有這個網址、沒有任何測試的東西。
- **只收元件來源的訊息**：`MessageEvent.origin` 不是 `http://localhost:61161`、或內容不是字串的訊息一律忽略（例如擴充功能送進來的）。送出時 `targetOrigin` 也寫死，視窗被導到別的網址就收不到請求（包括 PIN）。
- **一次點擊一個視窗**：瀏覽器一次點擊只讓開一個視窗。畫面在點擊的處理程式裡、還沒有任何 `await` 之前呼叫 `open()`，接下來的讀憑證或簽章用這個視窗；沒用到就關掉（例如題目的日期不對，第二次簽章前就停了）。
- **每個視窗一個新的名稱**：`window.open` 的視窗名稱是 `iamreal-` 加 128 位元的亂數，每次不同。名稱固定的話，用 `window.open` 開了這一頁的別的網站，可以用同一個名稱把元件的視窗導到別處（2026-11-16 在 Chrome 157 實測過）。上一個視窗關了才開下一個：請求結束時視窗就關，`open()` 也先關掉沒用到的那一個。頁面的 `Cross-Origin-Opener-Policy` 另外切斷開啟者和這一頁的關係（見「頁面需要的標頭」）。
- **視窗被擋時什麼都不送**：`open()` 回傳視窗有沒有開成。沒開成時畫面顯示「瀏覽器擋下了內政部元件的視窗。……」，不叫引擎往下做，同一個按鈕允許之後再按一次就繼續；流程不結束。萬一引擎還是叫了卡片，橋接回 `popup_blocked`，請求沒有離開頁面，引擎也當成可以重試的同一步。
- **回應嚴格讀**：憑證只交給引擎自己檢查；簽章的回應附的憑證（`certb64`）交給引擎，和讀卡時選出的那一張不同就停（`card_error`、代碼 `certificate_mismatch`）。回應沒有附憑證也停（`no_certificate_in_reply`）。
- **只送簽得對的內容**：要簽的字是 31 個 `[A-Za-z0-9:_.-]` 的字元（場合字串和宣告碼都是），以文字送出（2026-11-11 實測元件簽的是文字的位元組）。PIN 含 `+` 或 `%` 時不送：中華電信的程式庫送出前把 `+` 改寫成 `%2B`，看起來元件會像網址一樣解碼請求，這種 PIN 可能變成別的字送到卡片、用掉一次錯誤次數。

| 情況 | 引擎的停止原因 | 怎麼得知 |
|---|---|---|
| 視窗被擋（`window.open` 回 `null` 或丟出例外） | `card` `popup_blocked`（流程不結束，同一步再按一次） | 程式的行為；`test/e2e/ui.ts` 用沒有使用者動作的點擊讓無頭 Chrome 真的擋下 |

| 其他非 0 的 `ret_code`（例如 `0x7600000F` 禁止存取的網域） | `card_error`，代碼是十六進位的 `ret_code`（和 `last_error`） | 讀程式 |

## 每個值從哪裡來、送到哪裡去

| 值 | 從哪裡來 | 送到哪裡 |
|---|---|---|
| 憑證（含姓名、序號、公鑰） | 卡片（`Card.readCertificates`，不用 PIN） | 不送出。姓名只回給呼叫的程式顯示；序號只進建樹的 worker；整張憑證只進證明的私有輸入。沒被選上的那張（加密用，同樣有姓名）選完就清成 0；元件每次簽章附回來的副本比對完就清成 0；流程物件手上的那一份在送出後、取消、流程停下時清成 0。其他副本見「已知的限制」 |
| PIN | 呼叫的程式（`confirmCard(pin)`） | 只交給卡片。存在記憶體裡到第二次簽章完成、流程停下、或第一次簽章後 5 分鐘為止。JavaScript 的字串不能清成 0，做得到的是不再持有它的參照 |
| 卡片的兩個簽章 | 卡片（`Card.sign`） | 只進證明的私有輸入。場合字串的簽章在裝置上算成匿名編號。流程物件手上的那一份在送出後、取消、流程停下時清成 0；交給電路的輸入在算完證明後覆寫掉（見「已知的限制」） |
| 輸入的帳號 | 持卡人（第 4 步） | 紀錄（送出時）；按「預覽個人檔案」時，只有它放進平台帳號頁面的網址，在新分頁開（見「預覽個人檔案」） |
| 匿名編號 | 裝置自己算（`spec/scoped-id.ts`） | `POST /api/v1/card-state` 的內容（不放網址）；紀錄 |
| 場合字串 | 寫死的平台定義（`src/platforms.ts`，`src/spec/scope.ts` 的對照表由它產生），由持卡人選的平台決定 | 卡片簽；紀錄 |
| `current_time` | 裝置的時鐘，絕對時間換成 UTC+8 的日期（`src/spec/date.ts`），不用裝置設定的時區 | 證明的公開輸入 |
| 失敗的原因 | 裝置自己的檢查 | 只回給呼叫的程式（`FlowStop`）。沒有任何請求帶著它，也不寫進任何紀錄（`test/flow.test.ts` 每一個失敗的測試都檢查） |

## 唯一存進瀏覽器的東西

每把發證金鑰用過的最高清冊編號：`localStorage` 的 `iamreal.highest_crl_number.G2`、`iamreal.highest_crl_number.G3`，值是十進位的編號（`src/storage.ts`）。憑證、簽章、PIN、匿名編號、帳號名稱都不存。

## 頁面需要的標頭

伺服器對 `web/` 的每個檔案送三個標頭（`server/headers.go` 的 `pageHeaders`；`server/` 的測試檢查這份 README 引用的和它一字不差）：下面的 `Content-Security-Policy`、`Document-Isolation-Policy: isolate-and-credentialless`、`Cross-Origin-Opener-Policy: same-origin-allow-popups`。

### `Content-Security-Policy`

頁面自己不連到自己的網域以外的地方（測試實測：頁面和它的 worker 的每個請求都在自己的網域，元件的視窗除外）。這份政策在這之上擋住頁面裡的程式用 `fetch`、圖片、WebSocket、表單、iframe、別的來源的指令碼和 worker 把東西送到別處。

**它擋不住的**（2026-11-16 在 Chrome 157 實測，正式的建置、這份標頭，在頁面裡執行指令碼把字串送到另一個來源）：整頁的導覽（`location.assign("http://別處/?d=…")`）、點擊裡的 `window.open`、WebRTC（`RTCPeerConnection` 的 `iceServers` 指到別處，加上 `webrtc 'block'` 也一樣）都送得出去；`<link rel=preconnect>` 會對別處開連線（沒有資料，但用網域名稱帶資料出去沒有測）。CSP 不管頂層的導覽和 `window.open`，頁面自己就是靠這一點開元件的視窗。所以**這份政策不是「套件被動了手腳也送不出去」的保證**：bb.js、noir_js 和它們的依賴打包在頁面的主執行緒，和 PIN、憑證、簽章在同一個執行環境，見證也在主執行緒算。對「套件被動手腳」這件事，靠的是：執行時的套件釘死版本、鎖檔有完整性雜湊（`pnpm-lock.yaml`）、安裝時不執行套件的指令碼（pnpm 預設）、不安裝發布未滿 7 天的版本；之後再加上可重現的建置。worker 裡沒有導覽和 `RTCPeerConnection`，所以 worker 裡的程式確實只連得到自己的網域。

```
default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self'; img-src 'self'; style-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

- `'wasm-unsafe-eval'`：bb.js 和 Noir 要編譯 WebAssembly。
- `worker-src 'self'`：建樹的 worker 和 bb.js 自己的 worker 都是同一個網域的檔案。
- bb.js 原本把 WebAssembly 包成 `data:` 網址、把通用參數從 Aztec 的 CDN 下載。建置時把 WebAssembly 寫成檔案（`vite.config.ts`），通用參數改從自己的網域拿，所以 `connect-src` 只要 `'self'`。
- 畫面的樣式是同一個網域的 CSS 檔（`style-src 'self'`）；畫面不用 `style` 屬性，也沒有內嵌的 `<script>`。
- **元件的視窗不需要多開任何東西。** `window.open` 開 `http://localhost:61161/popupForm`（頂層的導覽）和 `postMessage` 都不受 CSP 管；頁面本身不對 `localhost:61161` 發任何請求，那些請求是元件的頁面自己發的。`test/e2e/ui.ts` 在這份標頭之下跑完整條流程，沒有任何違反。

無頭瀏覽器的測試在這份標頭之下跑完整條流程，並檢查沒有任何違反，頁面和它的 worker 沒有連到自己的網域以外的地方。`test/e2e/run.ts` 也檢查這份 README 引用的標頭和測試用的一字不差（`test/e2e/headers.ts`）；`test/e2e/ui.ts` 檢查後台實際送的和 `test/e2e/headers.ts` 相同。

### `Document-Isolation-Policy: isolate-and-credentialless`

多執行緒要頁面是跨來源隔離的。這個標頭讓 Chromium 系的桌機版隔離頁面，同時頁面還能和元件的視窗來回；`Cross-Origin-Opener-Policy: same-origin`（另一種隔離的做法）會讓元件的視窗沒有開啟者，回應送不回來。其他瀏覽器忽略它，證明用 1 個執行緒。

### `Cross-Origin-Opener-Policy: same-origin-allow-popups`

別的網站用 `window.open` 開這一頁時，沒有這個標頭的話，開啟者手上一直留著這一頁的參照：它能把整個分頁換成別的網址（例如長得一樣的假頁面），也能用元件視窗的名稱把那個視窗導到別處。這個值讓這一頁和開它的頁面分開（這一頁的 `window.opener` 是 `null`，開啟者手上的參照變成已關閉），而這一頁自己開的視窗（元件的）照樣有開啟者，元件的回應送得回來。它不讓頁面跨來源隔離，也不妨礙 `Document-Isolation-Policy` 的隔離。

`test/e2e/ui.ts` 在無頭的 Chrome、假元件之下檢查：讓另一個來源的頁面用 `window.open` 開這一頁，這一頁仍然是跨來源隔離的、`window.opener` 是 `null`、開啟者手上的參照是關閉的；這一頁讀卡時，開啟者用元件視窗的名稱 `window.open` 別的網址，元件的視窗不受影響、讀卡照常完成；開啟者改 `w.location`，這一頁不動。真的元件之下、Edge、Firefox、Safari 沒有測過。

## 怎麼單獨執行和測試

需要 Node 22（22.6 以上）、pnpm 10。

```
cd web
pnpm install --frozen-lockfile
pnpm fetch-crs        # 下載通用參數到 crs/（不進版控），核對 SHA-256
pnpm typecheck
pnpm test             # Node 裡的測試，約 20 秒（含一次正式的建置）
IAMREAL_BB=/path/to/bb pnpm test:e2e     # 引擎，無頭的 Chrome，約 2 分鐘
IAMREAL_BB=/path/to/bb pnpm test:ui      # 畫面、橋接、真的後台，無頭的 Chrome，約 3 分鐘（要 Go）
pnpm build            # 正式的建置，到 dist/
```

- `pnpm fetch-crs` 是這個目錄的程式唯一對外的連線（`pnpm local` 另外讓後台的清冊鏡像抓內政部的清冊）：從 `https://crs.aztec-cdn.foundation/` 下載 2^18 個點的 `g1_compressed.dat` 開頭 8 MiB（SHA-256 `5107a7926d504236331b4872b7218a1ca18921b5358d894822576e1aeb684934`）和 `g2.dat`（128 個位元組，`01797bfc4de5a96f0e516a9ea4537d18786dc30cb991aca4274c95822b69c32f`）。G1 的雜湊和 `bb` 自己下載、檢查過的兩份副本相同；G2 從 Aztec 的兩個網域下載的相同。頁面執行時從自己的網域拿這兩個檔案。
- `IAMREAL_BB` 是 `bb` 6.0.0（取得方式見 `verifier/README.md`）。`CHROME` 可以指定 Chrome 的路徑，預設是 macOS 的 Google Chrome。
- `pnpm test:e2e` 後面可以接設定，例如 `G3-dip G3-none G2-dip G3-dip-t4`：發證金鑰的大小、頁面是否跨來源隔離、證明的執行緒上限。

- 引擎初始化從頁面開始算，大部分是把壓縮的通用參數展開（單執行緒約 3.9 秒）。它在進頁面時就開始，和讀卡、建樹同時進行。展開後的參數不存起來（見上面「唯一存進瀏覽器的東西」），所以每次載入都重做。

- **分頁在背景時慢很多。** `test/e2e/background.ts`（2026-11-16，同一台電腦、Chrome 157 無頭模式，G3、自製的 176,000 筆清冊，每格兩次頁面載入、每次兩次過卡）：另一個分頁在前景、這一頁從載入到算完都在背景（`document.visibilityState` 是 `hidden`）時，跨來源隔離（8 個執行緒）的證明從 2.6 到 3.5 秒變成 28.6 到 32.5 秒，建樹從 2.5 到 2.9 秒變成 20.6 到 31.1 秒，引擎初始化從 1.8 到 1.9 秒變成 13.5 到 19.4 秒，整次過卡從 6.2 到 7.1 秒變成 56.5 到 66.8 秒；沒有隔離（1 個執行緒）的證明從 9.2 到 9.6 秒變成 60.3 到 65.2 秒，整次過卡從 12.4 到 14.4 秒變成 92.5 到 96.5 秒。原因沒有查（推測是 Chrome 降低背景分頁行程的優先順序）；有畫面的 Chrome 沒有量。
- 頁面不是跨來源隔離時 bb.js 不報錯、安靜地用 1 個執行緒；引擎自己看 `crossOriginIsolated` 和 `SharedArrayBuffer` 決定，並把 bb.js 自己說開的執行緒數一起告訴呼叫的程式（`ThreadMode`）。

## 已知的限制

- **名冊上的現況照後台說的顯示，不檢查。** 後台謊報（宣告的是 @bob 卻說沒宣告過）會讓持卡人不知情地用掉一次更換。要擋得下載整份名冊自己算，太重。後台從這裡查不出持卡人是誰，謊報會被名冊上的紀錄揭穿。裝置只擋名冊規則產生不出來的組合（見「從伺服器拿到的值」的表）；規則產生得出來的謊報擋不了。
- **CSP 不是「套件被動了手腳也送不出去」的保證。** 頁面裡的程式能用整頁的導覽、點擊裡的 `window.open`、WebRTC 把資料帶出去（見「頁面需要的標頭」）。被動了手腳的套件在主執行緒拿得到 PIN、整張憑證、場合字串的簽章。這一層靠的是版本釘死、鎖檔的完整性雜湊、安裝時不執行指令碼，之後的可重現建置。
- **bb.js 和 Noir 的 WebAssembly、頁面的指令碼沒有核對雜湊**（見「從伺服器拿到的值」下面的「頁面本身」）。頁面和靜態檔分開放時要補。
- **「清成 0」只清得到流程物件手上的那幾份。** 引擎清掉：流程物件的憑證和兩個簽章（送出後、取消、流程停下時）、讀卡時沒被選上的憑證（選完就清）、元件每次簽章附回來的憑證副本（比對完就清）、交給電路的輸入裡的數字陣列（算完證明就寫成 0，十六進位字串的陣列換成 `"0x0"`）。清不到、只是不再參照，留到被回收或分頁關掉的：證明引擎和 Noir 的 WebAssembly 記憶體、bb.js 的 worker 裡的見證（引擎整頁共用、不重啟）；交給電路的十六進位字串本身（JavaScript 的字串不能清成 0）、從簽章算出的大整數；元件回應的整個字串（含簽章和憑證的 base64）；姓名的字串。沒有到記憶體裡找過這些。
- **鏡像探得出這個瀏覽器記住的清冊編號。** 給一份編號 N 的清冊，裝置停不停下來，看它記住的編號比不比 N 大（`crl_rollback`）。編號每天增加，所以探得出這個瀏覽器上次過卡大約是哪一天。後台從名冊本來就知道每個匿名編號上次過卡的日期，多知道的很少。
- **兩次簽章之間換了卡，會對另一張卡用掉一次 PIN 的錯誤次數。** 第二次簽章用的是留著的 PIN，送給當時在讀卡機裡的卡；PIN 錯，流程結束，不會重送。
- **5 分鐘的上限管到 PIN 交給元件為止。** 讓卡片簽第二次之前引擎最後看一次時鐘；交給元件之後，那一步由橋接的上限結束（8 秒內沒準備好、30 秒內沒有回應），最晚約在 5 分鐘再加 38 秒。
- **清掉瀏覽器資料後，清冊編號的保護退回「清冊不能舊於 `L` 天」。** 換一個瀏覽器、無痕視窗也一樣。
- **頁面和 API 從同一台伺服器來時，這些檢查擋不住營運者本人**：改過的頁面可以不做這些檢查（ADR-0016）。
- PIN 是 JavaScript 的字串，沒辦法清成 0；做得到的是第二次簽章後（或流程停下、等了 5 分鐘時）不再持有它。
- **PIN 在兩次簽章之間留得比較久**：持卡人看現況、選、看後果的這段時間都在記憶體裡，最多 5 分鐘。分頁在背景、計時器被瀏覽器延後時，實際丟掉的時間可能晚一點（沒有量）；這段時間引擎不會再用它（每一步先看時鐘）。不想繼續的人按第 4、5 步的「取消」，PIN 立刻丟掉。
- **瀏覽器的密碼管理員會不會提議記住 PIN，沒有實測。** 欄位是 `autocomplete="off"`、沒有名稱、不在表單裡，但 Chrome 對密碼欄位不一定照 `autocomplete="off"`。無頭的 Chrome 沒有密碼管理員的提示可看。
- **元件的錯誤格式是讀程式得知的**（見「元件的橋接信任什麼」的表）。PIN 錯、鎖卡、沒有卡片的真實回應沒有實測；不認得的回應一律停下、顯示代碼，不猜、不重送。
- 只在 macOS 上的 Chrome 測過。Safari、Firefox、手機沒有跑過這裡的測試。`Cross-Origin-Opener-Policy: same-origin-allow-popups` 之下的元件視窗，只在無頭的 Chrome 和假元件之下測過。
