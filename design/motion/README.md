# design/motion

過卡流程兩段教操作的示範（[#369](https://github.com/iamreal-tw/iamreal/issues/369)）的時間表。網頁、Android、iOS 各自用自己的元件畫，讀的是這裡的同一份，所以三邊播的是同一段。為什麼這樣做在 `docs/research/teaching-animations.md`。

| 檔 | 內容 |
|---|---|
| `hang.json` | 掛上去：把島民證明的連結掛到 Threads 的個人檔案。20.7 秒，兩個平台共用，只差回程按哪一顆 |
| `sense.json` | 感應位置：卡片貼在手機背面的哪裡。Android、iPhone 各一組事件，播 3 輪後停住 |

示範旁邊的按鈕、給報讀器的說明寫在 `design/copy/`（`card-proof.md`「示範」、`hang.md`「示範」）。示意畫面長什麼樣子不在這裡：掛上去的在 `design/copy/hang.md`「示意圖」，感應位置的在各自施工的票。

## 三邊怎麼用

每一邊有一個純函式：給時間表、平台（`ios` 或 `android`）和秒數，算出那一刻的狀態。它不計時、不碰畫面、不記得上一次問的是幾秒，所以可以從頭重播、停在任何一格，三邊也能拿同一個秒數對答案。畫面只管把狀態畫出來；計時在它外面。

- 答案在 `spec/vectors/teaching-animation.json`：兩段示範各二十幾個秒數的狀態。三邊的測試都讀它。數字差在檔案寫的 `tolerance`（0.000001）以內算相同，其餘要逐字相同
- TypeScript 的那一份是 `worker/src/teaching-animation.ts`，網頁的播放程式帶的就是它。答案由 `worker/test/generate/teaching-animation.ts` 寫出：每一個答案手寫在裡面，寫檔前用那一份算一次，有一個不同就不寫
- `worker/test/teaching-animation.test.ts` 另外檢查兩份時間表自己說得通（下面每一節最後的「檢查」）
- 秒數小於 0 當作 0，超過全長當作全長：超過之後一直是最後一格
- 一個事件從它的 `at` 那一刻起算數（`at` 那一刻已經開始，走了 0 成）
- 一次按、一個紅圈結束的那一刻，狀態可以是「沒有」（`null`），也可以是一個完全透明的紅圈：畫出來相同，哪一種取決於小數怎麼進位。所以答案裡沒有落在這種時刻的秒數（差 0.001 秒以內），畫的那一邊兩種都要當成沒有

改時間表的秒數或順序，三邊的畫面跟著變；答案要重寫（改產生檔裡手寫的答案，重跑），三邊的測試才會過。

## 兩種緩動

`p` 是走過的時間佔全部的幾成（0 到 1）。

| 名稱 | 算法 | 用在 | CSS 裡最接近的 |
|---|---|---|---|
| 緩進緩出（三次方） | `p < 0.5` 時 `4p³`，否則 `1 − (2 − 2p)³ ÷ 2` | 鏡頭；感應位置的卡片上下移動 | `cubic-bezier(0.65, 0, 0.35, 1)` |
| 緩出（五次方） | `1 − (1 − p)⁵` | 紅圈；畫面內容的變化；感應位置的卡片滑進來 | `cubic-bezier(0.22, 1, 0.36, 1)` |

紅框的淡入淡出、按下去的深淺、卡片離開時的淡出是等速的。狀態裡的數字都已經套過緩動，畫的時候直接用。

## 掛上去：`hang.json`

五個示意畫面由左到右排成一列（`s0` 到 `s4`），只有鏡頭動。

| 欄位 | 意思 |
|---|---|
| `duration` | 全長，秒 |
| `picture` | 示範的畫面比例，寬比高 |
| `screen` | 一個示意畫面的寬是幾個單位。取景的 `span` 用同一種單位 |
| `start` | 開頭的取景 |
| `mark.fade` | 紅框和標籤淡入、淡出各幾秒 |
| `tap` | 按下去的數值，見「按」 |
| `states` | 六個畫面變化各花幾秒；0 是那一刻直接變 |
| `variants` | 每個平台自己的名字：事件裡的 `back`，iOS 是 `done3`，Android 是 `x3` |
| `boxes` | 每一個有名字的框：五個示意畫面，和畫面上會被按、被框、被鏡頭對準的地方 |
| `frames` | 每一個取景 |
| `events` | 事件，照時間排 |

### 框

`boxes` 列出每個框的名字和它是什麼。三邊畫示意畫面時，把這些名字掛在對應的元件上；時間表只用名字指它們，不寫座標。

兩個平台只差一個框。按了「新增連結」那一頁的「完成」、回到「連結」那一頁（`s3`）之後：

| 平台 | `back` 是 | 那一頁上 |
|---|---|---|
| iOS | `done3` | 右上角的「完成」 |
| Android | `x3` | 左上角的 ✕；右上角的「完成」是灰的，不能按 |

事件和取景裡寫 `back` 的地方，換成那個平台的名字再用。狀態裡出現的一律是換過的名字。

### 取景

```json
"done4": {"span": 327, "x": {"t": "done4", "a": 1, "v": 0.93}, "y": {"t": "done4", "a": 0.5, "v": 0.4}}
```

- `span`：示範的畫面有多寬，用示意畫面的單位。`span` 是 360 時，一個示意畫面剛好佔滿寬度；數字越小，拉得越近
- `x`、`y`：各自把框 `t` 的某一點（`a`，0 是左或上，1 是右或下）放在示範畫面的某一點（`v`，0 是左或上，1 是右或下）。兩個方向可以對不同的框

每一邊用自己排出來的位置算。示範畫面寬 `W`、高 `H`（實際的像素或點），一個示意畫面排出來寬 `S`，框 `t` 在那一列裡的左邊是 `left`、寬是 `width`：

```
縮放 = W ÷ (span × S ÷ screen)
橫向位移 = W × x.v − 縮放 × (left + width × x.a)
```

直向相同，用 `H`、`y` 和框的上邊、高。鏡頭在兩個取景之間時，縮放和兩個方向的位移各自照狀態的 `progress` 等比例內插。

### 事件

| `do` | 其他欄位 | 意思 |
|---|---|---|
| `camera` | `frame`、`dur` | 鏡頭用 `dur` 秒從現在的取景移到 `frame`，緩進緩出 |
| `mark` | `target` | 框 `target` 的紅框和標籤淡入 |
| `unmark` | `target` | 淡出 |
| `tap` | `target`，長按另有 `hold` | 按框 `target`；`hold` 是按住幾秒 |
| `state` | `state` | 畫面的內容改變，六種之一 |
| `step` | `step` | 現在示範的是四步文字裡的哪一步：0 是上面的兩顆按鈕，1 到 4 是四步，5 是結果 |

### 按

沒有 `hold` 的是按一下，有的是長按。`tap` 裡的數值：

| 欄位 | 意思 |
|---|---|
| `press` | 按到底時，蓋在按鈕上的墨色有多不透明 |
| `pressIn`、`pressHold`、`pressOut` | 按下去花幾秒；從開始到放開幾秒（長按再加 `hold`）；放開後幾秒恢復 |
| `ring`、`from`、`to` | 按一下的紅圈：一出現就是完整的，用 `ring` 秒從 `from` 倍放大到 `to` 倍，同時淡出，兩樣都緩出 |
| `holdIn`、`holdAt`、`holdOut` | 長按的紅圈：用 `holdIn` 秒從 `from` 倍長到 `holdAt` 倍，同時淡入，兩樣都緩出；停到手放開（從 `at` 起 `hold` 秒）；再用 `holdOut` 秒放大到 `to` 倍，同時淡出，兩樣都緩出 |

紅圈的倍數是相對於它自己畫出來的大小，圓心在框的正中間。框在紅圈還沒散完時就消失了也一樣（「貼上」的浮框）：紅圈留在框原本的位置散完。一次按從 `at` 開始，到紅圈和按鈕都恢復為止；之後狀態的 `tap` 是空的。

### 六個畫面變化

時間表只說哪一刻開始變、花幾秒；怎麼畫由各邊照示意圖決定，但走了幾成要照狀態的數字。

| `state` | 畫面上 |
|---|---|
| `copied` | 「複製連結」的字換成「已複製」 |
| `pasteMenu` | 網址欄上方出現「貼上」的浮框 |
| `pasted` | 浮框消失，網址填進欄位 |
| `linkListed` | 「連結」那一頁的清單多一列，「新增連結」往下移 |
| `linkOnProfile` | 個人檔案多一行連結，下面的東西往下移 |
| `resultLabel` | 那一行的墨色框和標籤「訪客找的就是這一行」出現 |

### 狀態

1.7 秒的那一刻（按了「複製連結」之後 0.3 秒）：

```json
{
 "camera": {"from": "s0", "to": "copy", "progress": 1},
 "marks": {"copy": 0.4},
 "tap": {"target": "copy", "pressed": 0.4, "ring": {"scale": 1.8515625, "opacity": 0.03125}},
 "states": {"copied": 0.99419, "pasteMenu": 0, "pasted": 0, "linkListed": 0, "linkOnProfile": 0, "resultLabel": 0},
 "step": 0
}
```

| 欄位 | 意思 |
|---|---|
| `camera` | 鏡頭在取景 `from` 到 `to` 的路上，走了 `progress`（套過緩動）。停著的時候 `progress` 是 1，鏡頭就是 `to`。第一次移動之前，兩個都是 `start` |
| `marks` | 紅框看得見的框，各自多不透明（大於 0，最多 1）。沒有列出來的是 0 |
| `tap` | 正在按的框、按下去幾成（`pressed`，乘上 `tap.press` 就是那層墨色的不透明度）、紅圈的倍數和不透明度。沒有在按時是 `null` |
| `states` | 六個畫面變化各走了幾成（套過緩動）。六個都在 |
| `step` | 最近一個 `step` 事件的值；還沒有就是 0 |

### 檢查

事件照時間排；每個 `target`、`frame` 和取景對準的框都有定義，兩個平台各查一次；同一個框的 `mark` 和 `unmark` 成對，而且淡入完了才淡出；鏡頭一次只做一個移動，一次只按一個地方；六個畫面變化各發生一次；`step` 只往後走，最後是 5；每個事件連同它花的時間都在全長之內。

## 感應位置：`sense.json`

手機正面朝著看的人，全程不動。卡片在手機後面，從右邊滑進來。

| 欄位 | 意思 |
|---|---|
| `rounds` | 播幾輪 |
| `rest` | 停住時的樣子：卡片留在最後的位置（`"card": "stays"`），沒有紅圈（`"ring": false`）。這一版只有這一種：算法照它寫死，測試檢查這兩個值沒有變。要換另一種停法，算法和答案一起改 |
| `enter.from` | 卡片從右邊多遠滑進來：幾個手機的寬 |
| `ring` | 紅圈從 `from` 倍放大到 `to` 倍，同時淡出，緩出。倍數相對於它自己畫出來的大小，圓心在卡片的中心 |
| `variants` | `android`、`ios` 各一組：一輪幾秒（`duration`）和那一輪的事件 |

卡片的高度寫的是卡片中心在手機的哪裡：手機高度的比例，0 是頂端，1 是底端。

| `do` | 其他欄位 | 意思 |
|---|---|---|
| `enter` | `y`、`dur` | 卡片在高度 `y` 從右邊滑進來，同時淡入，兩樣都緩出 |
| `move` | `y`、`dur` | 卡片移到高度 `y`，緩進緩出 |
| `ring` | `dur` | 感應到了：一個紅圈 |
| `leave` | `dur` | 卡片在原地淡出，等速。這一輪剩下的時間看不見，然後下一輪 |

事件的 `at` 是從那一輪開始算的秒數。最後一輪不離開：到了 `leave` 的那一刻就停住，卡片留在那裡。所以全長是 `duration × (rounds − 1) + leave 的 at`：Android 25.55 秒，iPhone 10.55 秒。

### 狀態

Android 7.25 秒的那一刻（紅圈放到一半）：

```json
{"round": 1, "stopped": false, "card": {"y": 0.375, "x": 0, "opacity": 1}, "ring": {"scale": 1.65625, "opacity": 0.03125}}
```

| 欄位 | 意思 |
|---|---|
| `round` | 第幾輪，從 1 開始 |
| `stopped` | 是不是已經停住。停住之後不論過多久都一樣 |
| `card` | 卡片中心的高度（`y`）、在定位的右邊幾個手機的寬（`x`，0 是到了）、多不透明。每一輪滑進來之前，卡片等在旁邊，看不見 |
| `ring` | 紅圈的倍數和不透明度；沒有紅圈時是 `null` |

### 檢查

每個平台的事件照時間排；先滑進來，最後離開，滑進來、紅圈、離開各一次；卡片一次只做一件事；高度在手機上；最後一個事件連同它花的時間在一輪之內。
