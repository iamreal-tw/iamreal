# app（Android、iOS）

只在手機 app 上出現、不屬於任何一個流程的文字。過卡的畫面在 `card-proof.md`。原則在 `docs/design/principles.md`。

`app.json` 是這一份給程式讀的形式，兩個 app 建置時原樣包進去。這裡每一個程式碼區塊的每一行是它的一個值，它的每一個值也都是這裡的一行，Android 的測試雙向核對（`AppCopyTest`），也核對每一種 app 的名稱在它自己的鍵底下（`AppNameTest`）。

## 主畫面上的名稱

手機主畫面上，app 圖示底下的名稱。Android 和 iOS 各有三種 app（ADR-0040），識別碼不同，三個可以同時裝在一支手機上，各有一個名稱。上線前正式 app 和測試 app 都連測試網站，兩個名稱都看得出是測試，而且彼此分得出來。

### 正式 app

識別碼 `tw.iamreal.app`，要變成正式版的那一個。上線前它在 Google Play 的封閉測試和 TestFlight，連的是測試網站：

```
島民證明 封測
```

- 「封測」是封閉測試：它是要變成正式版、現在在封閉測試的那一個
- 上線起它連正式網站，名稱改成 `島民證明`，和改連正式網站的是同一個 PR。`app.json` 現在放的是上線前的這一個

### 測試 app

識別碼 `tw.iamreal.app.test`，從 Google Play 的測試軌道和 TestFlight 裝：

```
島民證明 測試
```

- 「測試」：它是永遠連測試網站的那一個，上線後也是。上線後要在測試網站上測，從商店裝的就是它

### 開發用 build

識別碼 `tw.iamreal.app.dev`，不上傳商店，維護者用線裝：

```
島民證明 dev
```

- 它永遠連測試網站。和另外兩種裝在同一支手機上時，靠這個名稱分出哪一個是哪一個

### 三種都適用的

- 「島民證明」和後面的字之間是一個半形空格
- 這是第一版。正式的名稱在「[app 的名稱、商店頁和上架的地區](https://github.com/iamreal-tw/iamreal/issues/154)」定；定了之後改這裡，Android 和 iOS 一起改
- Android 和 iOS 的測試讀這一段，確認每一種 app 安裝檔裡的名稱和它相同（測試 app 的建置從 #483、#484 起）

## 啟動畫面

打開 app 時，第 1 步之前的畫面（`design/screens/app-splash-phone.png`）：記號在中間，底下一行是名稱和網址，中間用一條細的豎線隔開，和網頁頁首的名稱旁邊一樣（`design/DESIGN.md`「元件」的導覽列）。三種 app 都寫這一行，不畫測試的標示。

```
島民證明
iamreal.tw
```

## 讀卡的用途說明（iOS）

iOS 要讀 NFC 的 app 在 `Info.plist` 寫一句用途說明（`NFCReaderUsageDescription`，`ios/Config/Info.plist`），沒有這一句就不能讀卡。

```
感應自然人憑證，讀取卡片上的憑證、讓卡片簽章。
```

## 日子和時刻

提醒的日子和時刻在每個畫面都這樣寫。`{date}` 是 `2027-02-08` 這樣的日期，`{weekday}` 是下面七個裡的一個：

```
{date}（{weekday}）
星期一
星期二
星期三
星期四
星期五
星期六
星期日
```

時刻寫成時段、一個半形空格、12 小時制的 `h:mm`，例如「晚上 9:00」。0–11 時是上午，12–17 時是下午，18–23 時是晚上；12 小時制的 0 時寫 12：

```
上午
下午
晚上
```

下面的句子裡，`{day}` 是上面那一行（`2027-02-08（星期一）`），`{time}` 是時刻（`晚上 9:00`），兩個直接接在一起，中間不空格。

## 過卡提醒

照「[每三個月提醒過卡：app 在手機上存什麼](https://github.com/iamreal-tw/iamreal/issues/93)」。提醒是手機自己排的本機通知，不經過伺服器；手機上只存四樣：開關、間隔、時刻、下次提醒的日子。關掉提醒就四樣一起刪掉，所以關掉之後和從來沒開過一樣。過卡時問要不要提醒的那一步，在 `card-proof.md` 第 7 步（提醒）。

### 選間隔和時刻

從過卡第 7 步的「設定提醒」或「改提醒間隔或時刻」，或設定頁的開關和「更改」打開（`design/screens/app-reminder-2-schedule-phone.png`）：

```
提醒我回來過卡
從今天起算，落在同一個星期幾。

多久提醒一次
一個月（4 週）
三個月（12 週）
建議
六個月（26 週）
選日期

什麼時候提醒，卡片比較容易在手邊
時刻
更改

下次提醒：{day}{time}

開啟提醒
儲存
取消
```

- 「建議」標在三個月那一列的右邊。預設是三個月、晚上 9:00：自然人憑證多半放在家裡，小標「什麼時候提醒，卡片比較容易在手邊」請持卡人挑卡片在手邊的時候
- 一個月是 4 週、三個月是 12 週、六個月是 26 週，從今天起算，所以落在今天的星期幾
- 「選日期」打開系統選日期的視窗，可以選明天到一年後。選日期只管這一次：之後過卡完成時，照上一次選的間隔重排
- 「時刻」那一列的右邊是現在的時刻和「更改」，按了打開系統選時刻的視窗。改了之後一直沿用
- 「下次提醒」照畫面上選的直接算出來，選了就跟著變
- 提醒還沒開時，按鈕是「開啟提醒」；已經開著時是「儲存」

按「開啟提醒」才向系統要通知的權限（第 7 步和設定頁都是這個順序：先看到會在哪一天、幾點提醒，再問系統）。系統不允許這個 app 發通知時，什麼都不存，留在這個畫面，按鈕上面寫：

```
沒有排提醒：手機不允許這個 app 發通知。到手機的設定打開通知後，再回來開啟提醒。
```

### 通知

到了下次提醒的日子和時刻，通知一次（`design/screens/app-reminder-3-notification-phone.png`，示意）：

```
該回來過卡了
拿出自然人憑證，花 3 分鐘更新島民證明。
一週後再提醒我
```

- 第一行是標題，第二行是內文，第三行是通知上的按鈕
- 不寫帳號、不寫「你的」：一支手機可能過好幾個人的卡。不寫「到期」「快失效」
- 只通知一次。按「一週後再提醒我」，7 天後同一個時刻再通知一次，不限次數；沒有任何動作就不再通知，到下次過卡完成時再排
- 點通知本身，打開 app 的過卡第 1 步

Android 的通知要歸在一個類別，類別的名稱顯示在手機的設定裡（iOS 沒有）：

```
過卡提醒
```

### 從通知點進來

點了通知打開的第 1 步，在最上面（`design/screens/app-reminder-4-from-notification-phone.png`）：

```
這是過卡的提醒。現在不方便的話，可以晚點再做。
一週後再提醒我
```

- 按了之後，這一段換成下面這一句。不自動重排：沒有過完卡就離開，不會多排一次提醒
- 和「這一版的 app 從 … 起不能過卡」（`card-proof.md` 第 1 步的 app 段）同時出現時，那一句在上
- 過卡完成，這一段就不再出現

```
會在 {day}{time} 再提醒你。
```

## 設定

第 1 步和第 8 步（完成和分享）的頁首右邊有「設定」（`design/screens/app-settings-phone.png`）：

```
設定
返回
```

```
設定

過卡提醒
提醒我回來過卡
多久一次
一個月
三個月
六個月
更改
時刻
下次提醒
下次過卡完成後排

關於
版本
常見問題
隱私權說明
原始碼（GitHub）
```

- 「提醒我回來過卡」是一個開關。打開時照「選間隔和時刻」那個畫面選；關掉就取消排好的通知，刪掉手機上存的四樣
- 提醒關著時，不顯示「多久一次」「時刻」「下次提醒」三列
- 「多久一次」寫一個月、三個月或六個月（上次選了日期也寫間隔），右邊有「更改」；「時刻」寫時刻，右邊有「更改」；兩個「更改」都打開「選間隔和時刻」那個畫面
- 「下次提醒」寫 `{day}`；那一天的提醒已經通知過了，寫「下次過卡完成後排」
- 不寫手機上存了什麼、提醒不經過伺服器：對持卡人沒有用處（專案擁有者 2026-11-28）。手機上存的東西寫在「隱私權說明」（`privacy.md`），設定頁下面的「隱私權說明」打開它
- 「版本」的右邊是 app 的版本，上傳到商店時給的台灣日期（`2026.11.21`，`android/README.md`「三種 app」）；開發用 build 寫 `dev`
- 「常見問題」「隱私權說明」用瀏覽器打開網站的 `/faq`、`/privacy`；「原始碼（GitHub）」打開 `https://github.com/iamreal-tw/iamreal`。網站是這個 build 連的那一個（測試的 build 是測試網站）
