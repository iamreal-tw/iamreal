# 視覺設計

網頁、Android、iOS 長得一樣的規則。做任何畫面之前，先讀 `docs/design/principles.md`，再讀這一份。

| 檔 | 管什麼 |
|---|---|
| `docs/design/principles.md` | 畫面要說什麼、不能說什麼 |
| `design/copy/` | 每一句給人看的話 |
| `design/DESIGN.md`（這一份） | 看起來怎麼樣，以及為什麼 |
| `design/tokens.json` | 顏色、字級、間距的數值 |
| `design/screens/` | 每一頁、每一個畫面定稿的樣子 |

三份對不上時：文字以 `design/copy/` 為準，數值以 `tokens.json` 為準，截圖只是樣子。

## 方向

白底、墨色的字、粗明體的標題（源流明體 TW）。一個點代表一個帳號。整個網站只用一種插圖語言：一片點，大多是灰色空心，少數是藍綠色實心，其中一個紅點是「你」。

第一次來的人看第一眼就要懂：網路上有很多帳號，看不出來源；有些帳號已經有一張自然人憑證替它背書；你也可以是其中一個。

## 兩層：首頁和事實頁

原則分成兩層（`docs/design/principles.md`「首頁和事實頁」），視覺也跟著分。事實頁是首頁以外的每一頁和每一個畫面，清單寫在原則的那一節；連結預覽圖和首頁同一層。

| | 首頁、連結預覽圖 | 事實頁 |
|---|---|---|
| 插圖 | 點、證明卡、電腦和證明紀錄的示意圖 | 不放裝飾性的插圖，只靠字的大小排層次；教操作的示意圖可以（例如感應卡片的位置、掛上個人檔案的三步驟）：墨色線條，你的自然人憑證用紅色 |
| 藍綠色 | 示意圖和統計裡的「有島民證明的帳號」 | 不用。不放在帳號名稱旁邊當記號 |
| 最大的字 | 主標 | 島民證明頁和查詢頁是帳號名稱；過卡畫面是這一步的標題 |
| 動態 | 「你」脈動三次 | 沒有 |

理由：事實頁上的任何記號，都會被讀成「系統認證過這個帳號」（原則 4）。

## 數值怎麼用

`tokens.json` 的 key 就是 CSS 變數的名稱，值照 CSS 的寫法。兩份樣式表（訪客的頁面、過卡的網頁）和兩個 app 的主題各自寫數值，不從它產生檔案；各自有測試讀 `tokens.json` 比對。樣式表和主題只寫自己用到的變數，寫了的，數值要和 `tokens.json` 相同。

- 名稱後面加 `-phone` 的是手機排法用的值，沒有 `-phone` 的兩種排法都用
- `--breakpoint` 寫在 CSS 的 `@container`、`@media` 裡時不能用變數，直接寫數字，數字和它相同

## 顏色

每個顏色只代表一件事。新的畫面要用顏色時，先看它的意思對不對；對不上就用墨色。

| 變數 | 名稱 | 值 | 代表 | 不要用在 |
|---|---|---|---|---|
| `--bg` | 底 | `#FFFFFF` | 頁面的底 | |
| `--ink` | 墨 | `#141414` | 標題、重要的字；過卡進度清單的打勾 | |
| `--text` | 正文 | `#2E3135` | 段落 | |
| `--mute` | 次要 | `#5A5F64` | 小字、說明、「之後」 | 不能再淡，白底上要過 4.5:1（現在 6.4:1） |
| `--line` | 線 | `#E3E5E7` | 分隔線 | |
| `--soft` | 淺灰 | `#F6F7F7` | 讀到的卡片資料這類「只在這裡顯示」的區塊；要比對的連結的底 | 一般的強調 |
| `--dot` | 灰點 | `#CDD2D6` | 看不出來源的帳號 | 不寫成「可疑」「假的」 |
| `--proof` | 藍綠 | `#1D6B78` | 有島民證明的帳號；島民證明本身（例如地基那一塊） | 小標、底色、裝飾；事實頁上個別帳號的旁邊 |
| `--proof-soft` | 淺藍綠 | `#EEF5F6` | 地基的底 | 只用在地基 |
| `--proof-track` | 比例條的底 | `#D3E4E7` | 比例條沒有填滿的那一段 | 只用在比例條 |
| `--you` | 覆盆子紅 | `#BF2150` | 「你」；按鈕和連結；你的自然人憑證（示意圖裡的紅色卡片） | 警告、錯誤 |
| `--you-hover` | 深覆盆子紅 | `#A51A44` | 按鈕和連結滑過去時 | |

紅色同時是「你」、行動、你的卡片，意思是一致的：都是你的東西或你要做的事。

不用綠色，不用打勾（打勾只在過卡進度清單，用墨色）。不用漸層。

## 字

| 用途 | 字型 | 粗細 | 大小（桌機／手機） | 行高 |
|---|---|---|---|---|
| 主標 | 源流明體 TW | 700 | 60 ／ 依寬度，一行 9 字 | 1.24 |
| 段落標題 | 源流明體 TW | 700 | 40 ／ 28 | 1.34 |
| 小標題 | 源流明體 TW | 700 | 26 ／ 21 | 1.5 |
| 強調句、問句 | 源流明體 TW | 700 | 22 ／ 19 | 1.5 |
| 大數字 | 源流明體 TW | 700 | 132 ／ 76 | 1 |
| 帳號名稱（島民證明頁、查詢頁的第一屏） | 系統黑體 | 800 | 76 ／ 48 | 1.1 |
| 內文 | 系統黑體 | 400 | 18 ／ 16 | 1.85 |
| 段落上方的小標 | 系統黑體 | 400 | 15 ／ 14 | 1.6 |
| 小字 | 系統黑體 | 400 | 14 | 1.7 |
| 島民編號、網址 | 系統等寬字 | 400 | 依上下文 | |

對應的變數：字型 `--font-display`、`--font-body`、`--font-mono`；大小 `--size-h1`、`--size-h2`、`--size-h3`、`--size-lead`、`--size-figure`、`--size-account`、`--size-body`、`--size-kicker`、`--size-small`（手機加 `-phone`）；粗細 `--weight-heading`、`--weight-account`、`--weight-body`；行高 `--leading-h1`、`--leading-h2`、`--leading-h3`、`--leading-figure`、`--leading-account`、`--leading-body`、`--leading-kicker`、`--leading-small`。強調句和小標題同一個行高。

- **明體用源流明體 TW（GenRyuMin2 TW）**：台灣的柯志杰（ButTaiwan）做的開源字型，SIL OFL 1.1，字形照台灣教育部標準。這是台灣人的證明，用台灣團隊做的字有它的意思；它比思源宋體溫潤、末端不那麼尖。比較過思源宋體、源雲明體、源樣明體、昭源宋體（香港字形，不用）、霞鶩文楷和圓體（不夠正式）。
- **明體只有粗（B）一個字重，所有用明體的地方都是 700。** 之後主標要更粗，再加一個字重的子集。
- **只有明體要載入，而且只收用得到的字。** 子集提交在 `design/fonts/`，旁邊是 `OFL.txt` 和重新產生子集的腳本。子集收 `design/copy/` 的每一個字，加上可列印的 ASCII（帳號名稱、日期、數字是動態的）。改了 `design/copy/` 的人手動重跑腳本；測試檢查 `design/copy/` 的每一個字都在子集裡。部署和建置都不產生子集。
- **從我們自己的網域載入。** 訪客的頁面從自己的網域載入一份拷貝，過卡的網頁打包進自己的檔案，兩個 app 建置時包進去。不用 Google Fonts：每個訪客的連線都會經過第三方。
- **授權照 SIL OFL 1.1 走。** 子集是改作，可以照用原名（保留名稱只有 Adobe 的「Source」）；但每一份散佈的字型都要附著作權聲明和授權：做子集時保留 name 表的 13（授權說明）、14（授權網址），程式庫裡字型旁邊放一份 `OFL.txt`。授權不要求在頁面上標示；致謝寫在根目錄的 README。
- 內文用系統的黑體：蘋方、Noto Sans TC、微軟正黑，不載入。等寬字也用系統的。
- **標題的斷行要手動指定。** 在逗號後面斷，不讓瀏覽器把「卻不／一定」這樣的詞拆開。手機上主標一行 9 個字，字級跟著容器寬度算（扣掉兩側留白，除以 9.3）。
- 段落上方的小標用次要色的一般字，不用全大寫，不加色塊。
- 數字用等寬的數字字形（`tabular-nums`），大數字的千分位逗號下方要留空間給下一行。

## 點：一點代表一個帳號

- **灰色空心**（`--dot`，外徑 `--dot-ring`）：一則留言的帳號，看不出來源。
- **藍綠實心**（`--proof`，直徑 `--dot-filled`）：有一張台灣自然人憑證替這個帳號背書。
- **紅色實心加一圈**（`--you`，直徑 `--dot-you`）：你。整頁最多兩處（第一屏、第 4 段），只出現在一群點裡面，用來指出你的位置。

規則：

- 點的間距固定（`--dot-pitch`，18px），灰點畫在格線上，藍綠點和紅點落在同一個格線上。
- 藍綠點用個別放置的方式隨機分布，不用會重複的花紋（花紋看得出規律）。
- 要表達「越來越多」，用密度：一側稀疏、一側密集。
- 示意圖要有圖例；圖例的字和這一節的定義相同，寫在 `design/copy/`。
- 點只用在首頁和連結預覽圖。連結預覽圖每一頁都用同一張，圖上沒有帳號名稱。事實頁的畫面上不用點。

## 線

- **實線**：已經有的、現在就能用的。
- **虛線**：之後才會有的、還沒做的。也用在連到地基的線。
- 不用粗框把一段字框起來當強調；強調靠字的大小和明體。框只用在有意思的地方：證明紀錄、證明卡、地基和還沒蓋的服務（圓角 `--radius-panel`）。

## 版面

- 內容最寬 1200px（`--max-width`），兩側留白桌機 40px、手機 20px（`--gutter`）。
- 寬度小於 760px（`--breakpoint`）換成手機的排法（用容器的寬度判斷）：所有並排的欄改成上下排。並排的兩欄之間留 `--column-gap`。
- 段落之間上下各留 120px（手機 72px，`--section`），用一條細線分開。
- 每一段的排法要不同，不要五段都是「標題、段落、三欄」。
- 段落文字一行最多約 32 個全形字（`--measure`）。

## 元件

- **按鈕**：主要按鈕是覆盆子紅底、白字，高 56px（`--button-height`），圓角 4px（`--radius`）；手機上撐滿寬度。次要按鈕是墨色框、白底。一個畫面只有一個主要按鈕。
- **連結**：內文裡用覆盆子紅加底線；導覽列和頁尾用墨色，滑過去才出現底線。
- **導覽列**：桌機依序是記號、「島民證明」、`iamreal.tw`，右邊四個連結和「我要換島民證明」的按鈕。手機是記號、「島民證明」和「選單」：選單用不需要程式的展開元件（`<details>`）做，展開是同樣的四個連結加按鈕。`iamreal.tw` 和名稱之間用一條 1px 的豎線隔開，網址用同一套明體、15px、次要色，和「島民證明」的中線對齊（兩者都設行高 1、置中對齊）。中文和英文混排時，不同字型的中線和基線對不齊，所以網址也用明體。導覽列的字在 `design/copy/home.md`。
- **頁尾**：「島民證明 iamreal.tw」加連結。桌機一行；手機名稱一行，連結兩欄、每格 48px 高。連結的字和順序在 `design/copy/home.md`。
- **網址出現在哪裡**：頁首名稱旁、頁尾、島民證明頁要比對的連結（`iamreal.tw/p/…`，等寬字、淺灰底）。讓人記得網址、截圖轉貼時知道去哪裡查；它防不了釣魚，仿冒的網站會照抄畫面、換掉網址。
- **常見問題**：可展開的問答，問題之間用細線分開，右邊一個箭頭。
- **證明卡**（示意圖）：白底、墨色框，帳號名稱最大，下面是島民編號。不用紅色，和紅色的自然人憑證分開。
- **大數字和比例條**：兩個數字並排，下面一條比例條；條的總長是全部（`--proof-track`），藍綠那一段是其中一部分（`--proof`）。
- **地基**：淺藍綠底（`--proof-soft`）、藍綠實線框，是現在就有的島民證明；上面的服務用虛線框，各有一條虛線往下接到地基。

## 動態

整個網站只有一個會自己動的東西：「你」那一點，載入後脈動三次就停住（每次 `--pulse-duration`，共 `--pulse-count` 次），留下一圈靜止的外圈。系統設定減少動態的人，一開始就是靜止的。按了之後的回饋（展開、切換）可以有短暫的過渡。

## 無障礙

- 字和底的對比至少 4.5:1；大於 24px 的字至少 3:1。
- 鍵盤的焦點框是 3px（`--focus-ring`）墨色外框，不拿掉。
- 能按的東西至少 44×44px（`--min-target`）。
- 示意圖整張給一句說明（`role="img"` 加說明文字，說明寫在 `design/copy/`），裡面的點對螢幕閱讀器隱藏。
- 不靠顏色傳達唯一的資訊：藍綠點和灰點同時有實心和空心的差別。

## 不做的

- 鎖頭、盾牌、打勾（過卡進度清單以外）、綠色
- 漸層、玻璃效果、陰影堆疊
- 每一段都一樣的卡片排法
- 裝飾用的插圖、不帶意思的抽象圖形
- 第三方的字型、分析或追蹤程式
- 人像插圖
